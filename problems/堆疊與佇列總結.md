# 堆疊與佇列總結篇

## 堆疊與佇列的理論基礎

首先我們在[堆疊與佇列：來看看堆疊和佇列不為人知的一面](https://programmercarl.com/栈与队列理论基础.html)中講解了堆疊（stack）和佇列（queue）的理論基礎。

裡面提到了靈魂四問：

1. C++ 中 stack、queue 是容器（container）嗎？
2. 我們使用的 stack、queue 是屬於哪個版本的 STL？
3. 我們使用的 STL 中 stack、queue 是如何實作的？
4. stack、queue 提供疊代器（iterator）來遍歷（traversal）空間嗎？

相信不僅僅是 C++ 中有這些問題，那麼大家使用其他程式設計語言（programming language），也可以考慮一下這四個問題，堆疊和佇列是如何實作的。

堆疊與佇列是我們熟悉得不能再熟悉的資料結構，但它們的底層實作，很多同學都比較模糊，這其實就是基礎所在。

可以出一道面試題：堆疊裡面的元素（element）在記憶體（memory）中是連續分佈的嗎？

這個問題有兩個陷阱：

* 陷阱 1：堆疊是容器配接器（container adapter），底層容器使用不同的容器，導致堆疊內資料在記憶體中不一定是連續分佈的。
* 陷阱 2：預設情況下，預設底層容器是 deque，那麼 deque 在記憶體中的資料分佈是什麼樣的呢？答案是：不連續的，下文也會提到 deque。

所以這就是考察候選者基礎知識紮不紮實的好問題。

大家還是要多多重視起來！

了解了堆疊與佇列基礎之後，那麼可以用[堆疊與佇列：堆疊實作佇列](https://programmercarl.com/0232.用栈实现队列.html) 和 [堆疊與佇列：佇列實作堆疊](https://programmercarl.com/0225.用队列实现栈.html) 來練習一下堆疊與佇列的基本操作。

值得一提的是，在[堆疊與佇列：用佇列實作堆疊還有點彆扭](https://programmercarl.com/0225.用队列实现栈.html)中，其實只用一個佇列就夠了。

**一個佇列在模擬（simulation）堆疊彈出元素的時候只要將佇列頭部的元素（除了最後一個元素外）重新添加到佇列尾部，此時再去彈出元素就是堆疊的順序了。**

## 堆疊經典題目

### 堆疊在系統中的應用

如果還記得編譯原理的話，編譯器（compiler）在詞法分析（lexical analysis）的過程中處理括號（bracket）、大括號（brace）等這個符號的邏輯，就是使用了堆疊這種資料結構。

再舉個例子，Linux 系統中，cd 這個進入目錄（directory）的命令我們應該再熟悉不過了。

```
cd a/b/c/../../
```

這個命令最後進入 a 目錄，系統是如何知道進入了 a 目錄呢，這就是堆疊的應用。**這在 LeetCode 上也是一道題目，編號：71. 簡化路徑，大家有空可以做一下。**

**遞迴（recursion）的實作是堆疊：每一次遞迴呼叫（recursive call）都會把函數（function）的局部變數（local variable）、參數（parameter）值和返回位址（address）等壓入呼叫堆疊（call stack）中**，然後遞迴返回的時候，從堆疊頂（top of stack）彈出上一次遞迴的各項參數，所以這就是遞迴為什麼可以返回上一層位置的原因。

所以堆疊在電腦領域中應用是非常廣泛的。

有的同學經常會想學的這些資料結構有什麼用，也開發不了什麼軟體，大多數同學說的軟體應該都是視覺化的軟體例如 APP、網站之類的，那都是非常上層的應用了，底層很多功能的實作都是基礎的資料結構和演算法。

**所以資料結構與演算法的應用往往隱藏在我們看不到的地方！**

### 括號匹配問題

在[堆疊與佇列：系統中處處都是堆疊的應用](https://programmercarl.com/0020.有效的括号.html)中我們講解了括號匹配問題。

**括號匹配是使用堆疊解決的經典問題。**

建議要寫程式碼之前要分析好有哪幾種不匹配的情況，如果不動手之前分析好，寫出的程式碼也會有很多問題。

先來分析一下這裡有三種不匹配的情況，

1. 第一種情況，字串（string）裡左方向的括號多餘了，所以不匹配。
2. 第二種情況，括號沒有多餘，但是括號的類型沒有匹配上。
3. 第三種情況，字串裡右方向的括號多餘了，所以不匹配。

這裡還有一些技巧，在匹配左括號的時候，右括號先入堆疊，就只需要比較目前元素和堆疊頂相不相等就可以了，比左括號先入堆疊程式碼實作要簡單得多！

### 字串去重（deduplication）問題

在[堆疊與佇列：匹配問題都是堆疊的強項](https://programmercarl.com/1047.删除字符串中的所有相邻重复项.html)中講解了字串去重問題。
1047. 刪除字串中的所有相鄰重複項

解題思路就是可以把字串順序放到一個堆疊中，然後如果相同的話堆疊就彈出，這樣最後堆疊裡剩下的元素都是相鄰不相同的元素了。

在[堆疊與佇列：有沒有想過電腦是如何處理表式的？](https://programmercarl.com/0150.逆波兰表达式求值.html)中講解了求反波蘭記法（reverse Polish notation）。

## 佇列的經典題目

### 滑動視窗最大值問題

在[堆疊與佇列：滑動視窗裡求最大值引出一個重要資料結構](https://programmercarl.com/0239.滑动窗口最大值.html)中講解了一種資料結構：單調佇列（monotonic queue）。

這道題目還是比較繞的，如果第一次遇到這種題目，需要反覆琢磨琢磨。

主要思想是**佇列沒有必要維護視窗（sliding windows）裡的所有元素，只需要維護有可能成為視窗裡最大值的元素就可以了，同時保證佇列裡的元素數值是由大到小的。**

那麼這個維護元素單調（monotonic）遞減的佇列就叫做**單調佇列，即單調遞減或單調遞增的佇列。C++ 中沒有直接支援單調佇列，需要我們自己來一個單調佇列**。

而且**不要以為實作的單調佇列就是對視窗裡面的數進行排序（sorting），如果排序的話，那和優先佇列（priority queue）又有什麼區別了呢。**

設計單調佇列的時候，pop 和 push 操作要保持如下規則：

1. pop(value)：如果視窗移除的元素 value 等於單調佇列的出口元素，那麼佇列彈出元素，否則不用任何操作
2. push(value)：如果 push 的元素 value 大於入口元素的數值，那麼就將佇列入口的元素彈出，直到 push 元素的數值小於等於佇列入口元素的數值為止

保持如上規則，每次視窗移動的時候，只要問 `que.front()` 就可以回傳目前視窗的最大值。

一些同學還會對單調佇列有一些困惑，首先要明確的是，**題解中單調佇列裡的 pop 和 push 介面（interface），僅適用於本題。**

**單調佇列不是一成不變的，而是不同場景不同寫法**，總之要保證佇列裡單調遞減或遞增的原則，所以叫做單調佇列。

**不要以為本題中的單調佇列實作就是固定的寫法。**

我們用 deque 作為單調佇列的底層資料結構，C++ 中 deque 是 stack 和 queue 預設的底層實作容器（這個我們之前已經講過），deque 是可以兩邊擴展的，而且 deque 裡元素並不是嚴格的連續分佈的。


### 求前 K 個高頻元素

在[堆疊與佇列：求前 K 個高頻元素和佇列有啥關係？](https://programmercarl.com/0347.前K个高频元素.html)中講解了求前 K 個高頻元素。

透過求前 K 個高頻元素，引出另一種佇列就是**優先佇列**。

什麼是優先佇列呢？

其實**就是一個披著佇列外衣的堆積（heap）**，因為優先佇列對外介面只是從隊頭取元素，從隊尾添加元素，再無其他取元素的方式，看起來就是一個佇列。

而且優先佇列內部元素是自動依照元素的權重（weight）排列。那麼它是如何有序排列的呢？

預設情況下 priority_queue 利用最大堆（max heap）完成對元素的排序，這個最大堆是以 vector 為表現形式的完全二元樹（complete binary tree）。

什麼是堆積呢？

**堆積是一棵完全二元樹，樹中每個節點（node）的值都不小於（或不大於）其左右孩子的值。**如果父親節點是大於等於左右孩子就是最大堆，小於等於左右孩子就是最小堆積（min heap）。

所以大家經常說的最大堆（堆頭是最大元素），最小堆積（堆頭是最小元素），如果懶得自己實作的話，就直接用 priority_queue（優先佇列）就可以了，底層實作都是一樣的，從小到大排就是最小堆積，從大到小排就是最大堆。

本題就要**使用優先佇列來對部分頻率進行排序。**注意這裡是對部分資料進行排序而不需要對所有資料排序！

所以排序的過程的時間複雜度（time complexity）是 $O(\log k)$，整個演算法的時間複雜度是 $O(n\log k)$。
