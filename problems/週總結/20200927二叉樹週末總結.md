## 週一

本週我們開始講解了二元樹，在[關於二元樹，你該了解這些！](https://programmercarl.com/二叉树理论基础.html)中講解了二元樹的理論基礎。

有同學會把紅-黑樹（red-black tree）和平衡二元搜尋樹（binary search tree, BST）弄分開了，其實紅-黑樹就是一種平衡BST，這兩個樹（tree）不是獨立的，所以 C++ 中 map、multimap、set、多（重）集（multiset） 的底層實作機制是平衡BST，再具體一點是紅-黑樹。

對於二元樹節點（node）的定義，C++ 程式碼如下：

```CPP
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(NULL), right(NULL) {}
};
```
對於這個定義中 `TreeNode(int x) : val(x), left(NULL), right(NULL) {}` 有同學不清楚幹什麼的。

這是建構子（constructor），這麼說吧，C 語言中的結構（struct）是 C++ 中類別（class）的祖先，所以 C++ 結構也可以有建構子。

建構子也可以不寫，但是 new 一個新的節點的時候就比較麻煩。

例如有建構子，定義初始值為 9 的節點：

```
TreeNode* a = new TreeNode(9);
```

沒有建構子的話就要這麼寫：

```CPP
TreeNode* a = new TreeNode();
a->val = 9;
a->left = NULL;
a->right = NULL;
```

在介紹前中後序遍歷（traversal）的時候，有遞迴（recursion）和疊代（iteration）（非遞迴），還有一種超強的遍歷方式：Morris 遍歷。

Morris 遍歷是二元樹遍歷演算法的超強進階演算法，Morris 遍歷可以將非遞迴遍歷中的空間複雜度（space complexity）降為 O(1)，感興趣大家就去查一查學習學習，比較小眾，面試幾乎不會考。我其實也沒有研究過，就不做過多介紹了。

## 週三

在[二元樹：聽說遞迴能做的，堆疊也能做！](https://programmercarl.com/二叉树的迭代遍历.html)中我們開始用堆疊（stack）來實作遞迴的寫法，也就是所謂的疊代法。

細心的同學發現文中前後序遍歷 空節點（null node） 是否入堆疊寫法是不同的

其實 空節點 入不入堆疊都差不多，但感覺 空節點 不入堆疊確實清晰一些，符合文中動畫的演示。

拿前序遍歷來舉例，空節點 入堆疊：

```CPP
class Solution {
public:
    vector<int> preorderTraversal(TreeNode* root) {
        stack<TreeNode*> st;
        vector<int> result;
        st.push(root);
        while (!st.empty()) {
            TreeNode* node = st.top();                      // 中
            st.pop();
            if (node != NULL) result.push_back(node->val);
            else continue;
            st.push(node->right);                           // 右
            st.push(node->left);                            // 左
        }
        return result;
    }
};
```

前序遍歷 空節點 不入堆疊的程式碼：（注意註解部分和上文的區別）

```CPP
class Solution {
public:
    vector<int> preorderTraversal(TreeNode* root) {
        stack<TreeNode*> st;
        vector<int> result;
        if (root == NULL) return result;
        st.push(root);
        while (!st.empty()) {
            TreeNode* node = st.top();                       // 中
            st.pop();
            result.push_back(node->val);
            if (node->right) st.push(node->right);           // 右（null node 不入堆疊）
            if (node->left) st.push(node->left);             // 左（null node 不入堆疊）
        }
        return result;
    }
};
```


在實作疊代法的過程中，有同學問了：遞迴與疊代究竟誰優誰劣呢？

從時間複雜度（time complexity）上其實疊代法和遞迴法差不多（在不考慮函數（function）呼叫開銷和函數呼叫產生的堆疊開銷），但是空間複雜度上，遞迴開銷會大一些，因為遞迴需要系統堆疊存參數（parameter）、轉回值（return value）等等。

遞迴更容易讓程式設計師理解，但收斂不好，容易堆疊溢出（stack overflow）。

這麼說吧，遞迴是方便了程式設計師，難為了機器（各種儲存參數，各種進堆疊出堆疊）。

**在實際專案開發的過程中我們是要盡量避免遞迴！因為專案程式碼參數、呼叫關係都比較複雜，不容易控制遞迴深度（depth），甚至會堆疊溢出。**

## 週六

在[二元樹：你真的會翻轉二元樹嗎？](https://programmercarl.com/0226.翻转二叉树.html)中我們把翻轉二元樹這麼一道簡單又經典的問題，充分地剖析了一波，相信就算做過這道題目的同學，看完本篇之後依然有所收穫！


**文中我指的是遞迴的中序橫過（inorder traversal）是不行的，因為使用遞迴的中序橫過，某些節點的左右孩子會翻轉兩次。**

如果非要使用遞迴中序的方式寫，也可以，如下程式碼就可以避免節點左右孩子翻轉兩次的情況：

```
class Solution {
public:
    TreeNode* invertTree(TreeNode* root) {
        if (root == NULL) return root;
        invertTree(root->left);         // 左
        swap(root->left, root->right);  // 中
        invertTree(root->left);         // 注意 這裡依然要遍歷左孩子，因為中間節點已經翻轉了
        return root;
    }
};
```

程式碼雖然可以，但這畢竟不是真正的遞迴中序橫過了。

但使用疊代方式統一寫法的中序是可以的。

程式碼如下：

```
class Solution {
public:
    TreeNode* invertTree(TreeNode* root) {
        stack<TreeNode*> st;
        if (root != NULL) st.push(root);
        while (!st.empty()) {
            TreeNode* node = st.top();
            if (node != NULL) {
                st.pop();
                if (node->right) st.push(node->right);  // 右
                st.push(node);                          // 中
                st.push(NULL);
                if (node->left) st.push(node->left);    // 左

            } else {
                st.pop();
                node = st.top();
                st.pop();
                swap(node->left, node->right);          // 節點處理邏輯
            }
        }
        return root;
    }
};


```

為什麼這個中序就是可以的呢，因為這是用堆疊來遍歷，而不是靠指標（pointer）來遍歷，避免了遞迴法中翻轉了兩次的情況，大家可以畫圖理解一下，這裡有點意思的。
