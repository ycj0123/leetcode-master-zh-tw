
# 本週小結！（二元樹（binary tree）系列三）


## 週一

在[二元樹：以為使用了遞迴（recursion），其實還隱藏著回溯（backtracking）](https://programmercarl.com/二叉树中递归带着回溯.html)中，透過 LeetCode [257.二元樹的所有路徑這道題目](https://programmercarl.com/0257.二叉树的所有路径.html)，講解了遞迴如何隱藏著回溯，一些程式碼把回溯的過程都隱藏了起來，甚至刷過這道題的同學可能都不知道自己用了回溯。

文章中第一版程式碼把每一個細節都展示出來了，大家可以清晰地看到回溯的過程。

然後給出了第二版最佳化後的程式碼，分析了其回溯隱藏在了哪裡，如果要把這個回溯抽出來，在第二版的基礎上應該怎麼改。

主要需要理解：**回溯隱藏在 traversal(cur->left, path + "->", result); 中的 path + "->"。每次函數（function）呼叫完，path 依然是沒有加上 "->" 的，這就是回溯了。**


## 週二

在文章[二元樹：做了這麼多題目了，我的左葉子之和是多少？](https://programmercarl.com/0404.左叶子之和.html)中提供了另一個判斷節點（node）屬性的解題思路，平時我們習慣了透過節點的左右孩子判斷本節點的屬性，但發現使用這個想法無法判斷左葉子。

此時需要相連的三層之間構成的約束條件，也就是要透過節點的父節點（father node）以及孩子節點來判斷本節點的屬性。

這道題目可以擴展大家對二元樹的解題思路。


## 週三

在[二元樹：我的左下角的值是多少？](https://programmercarl.com/0513.找树左下角的值.html)中的題目如果使用遞迴的寫法還是有點難度的，層次序走訪（level order traversal）反而很簡單。

題目其實是要在樹（tree）的**最後一列**找到**最左邊的值**。

**如何判斷是最後一列呢，其實就是深度（depth）最大的葉節點（leaf node）一定是最後一列。**

在這篇文章中，我們使用遞迴演算法實實在在地求了一次深度，然後使用靠左的遍歷（traversal），保證求得靠左的最大深度，而且又一次使用了回溯。

如果對二元樹的高度（height）與深度又有點模糊了，再看這裡[二元樹：我平衡嗎？](https://programmercarl.com/0110.平衡二叉树.html)，回憶一下吧。

[二元樹：我的左下角的值是多少？](https://programmercarl.com/0513.找树左下角的值.html)中把我們之前講過的內容都過了一遍，此外，還用前序遍歷（preorder traversal）的技巧求得了靠左的最大深度。

**求二元樹的各種最值，就想應該採用什麼樣的遍歷順序，確定了遍歷順序，其實就和陣列（array）求最值一樣容易了。**


## 週四

在[二元樹：遞迴函數（recursive function）究竟什麼時候需要轉回值（return value），什麼時候不要轉回值？](https://programmercarl.com/0112.路径总和.html)中透過兩道題目，徹底說清楚遞迴函數的轉回值問題。

一般情況下：**如果需要搜尋整棵二元樹，那麼遞迴函數就不要轉回值，如果要搜尋其中一條符合條件的路徑（path），遞迴函數就需要轉回值，因為遇到符合條件的路徑了就要及時回傳。**

特別是有些時候遞迴函數的轉回值是 bool 類型，一些同學會疑惑為啥要加這個，其實就是為了找到一條邊（edge）立刻回傳。

其實還有一種就是後序遍歷（post-order traversal）需要根據左右遞迴的轉回值推出中間節點的狀態（state），這種需要有轉回值，例如[222.完全二元樹](https://programmercarl.com/0222.完全二叉树的节点个数.html)，[110.平衡二元樹（balanced binary tree）](https://programmercarl.com/0110.平衡二叉树.html)，這幾道我們之前也講過。

## 週五

之前都是講解遍歷二元樹，這次該構造二元樹了，在[二元樹：構造二元樹登場！](https://programmercarl.com/0106.从中序与后序遍历序列构造二叉树.html)中，我們透過前序和中序橫過（inorder traversal），後序和中序，構造了唯一的一棵二元樹。

**構造二元樹有三個注意的點：**

* 分割時候，堅持區間（interval）不變（invariant）原則，左閉右開，或者左閉右閉。
* 分割的時候，注意後序或者前序已經有一個節點作為中間節點了，不能繼續使用了。
* 如何使用切割後的後序陣列來切合中序陣列？利用中序陣列大小一定是和後序陣列的大小相同這一特點來進行切割。

這道題目程式碼實作並不簡單，大家啃下來之後，二元樹的構造應該不是問題了。

**最後我還給出了為什麼前序和後序不能唯一構成一棵二元樹，因為沒有中序橫過就無法確定左右部分，也就無法分割。**

## 週六

知道了如何構造二元樹，那麼使用一個固定做法就可以解決文章[二元樹：構造一棵最大的二元樹](https://programmercarl.com/0654.最大二叉树.html)中的問題。

**注意類似用陣列構造二元樹的題目，每次分隔盡量不要定義新的陣列，而是透過下標（subscript）索引（index）直接在原陣列上操作，這樣可以節約時間和空間上的開銷。**

文章中我還給出了遞迴函數什麼時候加 if，什麼時候不加 if，其實就是控制 空節點（null node）（空指標（null pointer））是否進入遞迴，是不同的程式碼實作方式，都是可以的。

**一般情況來說：如果讓 空節點（空指標）進入遞迴，就不加 if，如果不讓 空節點 進入遞迴，就加 if 限制一下，終止條件（termination condition）也會相應地調整。**
