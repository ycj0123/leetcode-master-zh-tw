

# 本週小結！（二元樹（binary tree）系列四）

> 這已經是二元樹的第四週總結了，二元樹是非常重要的資料結構，也是面試中的常客，所以有必要一步一步幫助大家徹底掌握二元樹！

## 週一

在[二元樹：合併兩個二元樹](https://programmercarl.com/0617.合并二叉树.html)中講解了如何合併兩個二元樹，平時我們都習慣了操作一個二元樹，一起操作兩個樹（tree）可能還有點陌生。

其實固定做法是一樣的，只不過一起操作兩個樹的指標（pointer），我們之前講過求[二元樹：我對稱嗎？](https://programmercarl.com/0101.对称二叉树.html)的時候，已經初步涉及了一起遍歷（traversal）兩棵二元樹了。

**疊代（iteration）法中，一般一起操作兩個樹都是使用佇列（queue）模擬（simulation）類似層次序走訪（level order traversal），同時處理兩個樹的節點（node），這種方式最好理解，如果用模擬遞迴（recursion）的想法的話，要複雜一些。**

## 週二

週二開始講解一個新的樹，二元搜尋樹（binary search tree, BST），開始要換一個思路了，如果沒有利用好二元搜尋樹的特性，就容易把簡單題做成了難題了。

學習[二元搜尋樹的特性](https://programmercarl.com/0700.二叉搜索树中的搜索.html)，還是比較容易的。

大多數二元搜尋樹的題目，其實都離不開中序橫過（inorder traversal），因為這樣就是有序（ordered）的。

至於疊代法，相信大家看到文章中如此簡單的疊代法的時候，都會感動得痛哭流涕。

## 週三

了解了二元搜尋樹的特性之後，開始驗證[一棵二元樹是不是二元搜尋樹](https://programmercarl.com/0098.验证二叉搜索树.html)。

首先在此強調一下二元搜尋樹的特性：

* 節點的左子樹（left subtree）只包含小於當前節點的數。
* 節點的右子樹（right subtree）只包含大於當前節點的數。
* 所有左子樹和右子樹自身必須也是二元搜尋樹。

那麼我們在驗證二元搜尋樹的時候，有兩個陷阱：

* 陷阱一

**不能單純地比較左節點小於中間節點，右節點大於中間節點就完事了**，而是左子樹都小於中間節點，右子樹都大於中間節點。

* 陷阱二

在一個有序序列（sequence）求最值的時候，不要定義一個總體變數（global variable），然後遍歷序列更新總體變數求最值。因為最值可能就是 int 或者 long long 的最小值。

推薦要透過前一個數值（pre）和後一個數值比較（cur），得出最值。

**在二元樹中透過兩個前後指標作比較，會經常用到**。

本文[二元樹：我是不是一棵二元搜尋樹](https://programmercarl.com/0098.验证二叉搜索树.html)中疊代法為什麼沒有週一那篇那麼簡潔了呢，因為本篇是驗證二元搜尋樹，前提預設（default）它是一棵普通二元樹，所以還是要回歸之前老辦法。

## 週四

了解了[二元搜尋樹](https://programmercarl.com/0700.二叉搜索树中的搜索.html)，並且知道[如何判斷二元搜尋樹](https://programmercarl.com/0098.验证二叉搜索树.html)，本篇就很簡單了。

**要知道二元搜尋樹和中序橫過是好朋友！**

在[二元樹：搜尋樹的最小絕對差](https://programmercarl.com/0530.二叉搜索树的最小绝对差.html)中強調了要利用搜尋樹的特性，把這道題目想像成在一個有序陣列（ordered array）上求兩個數最小差值，這就是一道送分題了。

**需要明確：在有序陣列求任意兩數最小值差等價於相鄰兩數的最小值差**。

同樣本題也需要用 pre 節點記錄 cur 節點的前一個節點。（這種寫法一定要掌握）

## 週五

此時大家應該知道遇到二元搜尋樹，就想成是有序陣列，那麼在二元搜尋樹中求二元搜尋樹 mode 就很簡單了。

在[二元樹：我的 mode 是多少？](https://programmercarl.com/0501.二叉搜索树中的众数.html)中我給出了如果是普通二元樹，應該如何求 mode 的集合（set），然後進一步講解了二元搜尋樹應該如何求 mode 集合。

在求 mode 集合的時候有一個技巧，因為題目中 mode 是可以有多個的，所以一般的方法需要遍歷兩遍才能求出 mode 的集合。

**但可以遍歷一遍就可以求 mode 集合，使用了適時清空結果集（result set）的方法**，這個方法還是很巧妙的。相信仔細讀了文章的同學會驚呼其巧妙！

**所以大家不要看題目簡單了，就不動手做了，我選的題目，一般不會簡單到不用動手的程度**。

## 週六

在[二元樹：共用源始問題](https://programmercarl.com/0236.二叉树的最近公共祖先.html)中，我們開始講解如何在二元樹中求共用源始的問題，本來是打算和二元搜尋樹一起講的，但發現篇幅過長，所以先講二元樹的共用源始問題。

**如果找到一個節點，發現左子樹出現節點 p，右子樹出現節點 q，或者左子樹出現節點 q，右子樹出現節點 p，那麼該節點就是節點 p 和 q 的最低共用源始（lowest common ancestor）。**

這道題目看程式碼比較簡單，而且好像也挺好理解的，但是如果把每一個細節理解到位，還是不容易的。

主要思考如下幾點：

* 如何由下而上（bottom-up）遍歷？
* 遍歷整棵樹，還是遍歷局部樹？
* 如何把結果傳到根節點（root node）的？

這些問題都需要弄清楚，上來直接看程式碼的話，是可能想不到這些細節的。

共用源始問題，還是有難度的，初學者還是需要慢慢消化！

## 總結

本週我們講了[如何合併兩個二元樹](https://programmercarl.com/0617.合并二叉树.html)，了解了如何操作兩個二元樹。

然後開始另一種樹：二元搜尋樹，了解[二元搜尋樹的特性](https://programmercarl.com/0700.二叉搜索树中的搜索.html)，然後[判斷一棵二元樹是不是二元搜尋樹](https://programmercarl.com/0098.验证二叉搜索树.html)。

了解以上知識之後，就開始利用其特性，做一些二元搜尋樹上的題目，[求最小絕對差](https://programmercarl.com/0530.二叉搜索树的最小绝对差.html)，[求 mode 集合](https://programmercarl.com/0501.二叉搜索树中的众数.html)。

接下來，開始求二元樹與二元搜尋樹的共用源始問題，單篇篇幅原因，先單獨介紹[普通二元樹如何求最低共用源始](https://programmercarl.com/0236.二叉树的最近公共祖先.html)。

現在已經講過了幾種二元樹了，二元樹，平衡二元樹（balanced binary tree），完全二元樹（complete binary tree），二元搜尋樹，後面還會有平衡二元搜尋樹（balanced binary search tree）。那麼一些同學難免會有混亂了，我針對如下三個問題，幫大家再梳理一遍：

1. 平衡二元搜尋樹是不是二元搜尋樹和平衡二元樹的結合？

是的，是二元搜尋樹和平衡二元樹的結合。

2. 平衡二元樹與完全二元樹的區別在於底層節點的位置？

是的，完全二元樹底層必須是從左到右連續的，且次底層是滿的。

3. 堆積（heap）是完全二元樹和排序（sorting）的結合，而不是平衡二元搜尋樹？

堆積是一棵完全二元樹，同時保證父子節點的順序關係（有序）。**但完全二元樹一定是平衡二元樹，堆積的排序是父節點（father node）大於子節點（child node），而搜尋樹是父節點大於左孩子，小於右孩子，所以堆積不是平衡二元搜尋樹**。

大家如果每天堅持跟下來，會發現又是充實的一週！[機智]
