# 本週小結！（動態規劃系列一）

這週我們正式開始動態規劃（dynamic programming, DP）的學習！

## 週一

在[關於動态规劃，你該了解這些！](https://programmercarl.com/动态规划理论基础.html)中我們講解了動態規劃的基礎知識。

首先講一下動規和貪心法（greedy）的區別，其實大家不用太強調理論上的區別，做做題，就感受出來了。

然後我們講了動規的五部曲：

1. 確定 dp 陣列（array）（dp table）以及索引（index）的含義
2. 確定遞迴公式（recurrence formula）
3. dp 陣列如何初始化（initialization）
4. 確定遍歷（traversal）順序
5. 舉例推導 dp 陣列

後續我們在講解動規的題目時候，都離不開這五步！

本週都是簡單題目，大家可能會感覺按照這五步來好麻煩，憑感覺隨手一寫，直接就過，越到後面越會感覺，憑感覺這個事還是不靠譜的。

最後我們講了動態規劃題目應該如何 debug，相信一些錄友做動規的題目，一旦發生錯誤也是憑感覺來改。

其實只要把 dp 陣列印出來，哪裡有問題一目了然！

**如果程式碼寫出來了，一直 AC 不了，靈魂三問：**

1. 這道題目我舉例推導狀態變遷方程式（state transition equation）了嗎？
2. 我印出 dp 陣列的日誌（log）了嗎？
3. 印出來的 dp 陣列和我想的一樣嗎？

專治各種程式碼寫出來了但 AC 不了的疑難雜症。

## 週二

這道題目[動态规劃：斐波那契數](https://programmercarl.com/0509.斐波那契数.html)是當之無愧的動規入門題。

簡單題，我們就是用來了解方法論的，用動規五部曲走一遍，題目其實已經把遞迴公式，和 dp 陣列如何初始化都給我們了。

## 週三

[動态规劃：爬樓梯](https://programmercarl.com/0070.爬楼梯.html)這道題目其實就是斐波那契序列（Fibonacci sequence）。

但正常思考過程應該是推導完遞迴公式之後，發現這是斐波那契，而不是上來就知道這是斐波那契。

在這道題目的第三步，確認 dp 陣列如何初始化，其實就可以看出來，對 `dp[i]` 定義理解的深度。

`dp[0]` 其實就是一個無意義的存在，不用去初始化 `dp[0]`。

有的題解是把 `dp[0]` 初始化為 1，然後遍歷的時候 `i` 從 2 開始遍歷，這樣是可以解題的，然後強行解釋一波 `dp[0]` 應該等於 1 的含義。

一個嚴謹的思考過程，應該是初始化 `dp[1] = 1`，`dp[2] = 2`，然後 `i` 從 3 開始遍歷，程式碼如下：

```CPP
dp[1] = 1;
dp[2] = 2;
for (int i = 3; i <= n; i++) { // 注意 i 是從 3 開始的
    dp[i] = dp[i - 1] + dp[i - 2];
}
```

這個可以是面試的一個小問題，考察候選人對 `dp[i]` 定義的理解程度。

這道題目還可以繼續深化，就是一步一個台階、兩個台階、三個台階，直到 m 個台階，有多少種方法爬到 n 階樓頂。

這又有難度了，這其實是一個無界背包問題（unbounded knapsack problem），但 LeetCode 上沒有這種題目，所以後續我在講解背包問題（knapsack problem）的時候，今天這道題還會從背包問題的角度上來再講一遍。

這裡我先給出我的實作程式碼：

```CPP
class Solution {
public:
    int climbStairs(int n) {
        vector<int> dp(n + 1, 0);
        dp[0] = 1;
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) { // 把 m 換成 2，就可以 AC 爬樓梯這道題
                if (i - j >= 0) dp[i] += dp[i - j];
            }
        }
        return dp[n];
    }
};
```

程式碼中 `m` 表示最多可以爬 `m` 個台階。

**以上程式碼不能執行哈，我主要是為了體現只要把 `m` 換成 2，貼過去，就可以 AC 爬樓梯這道題，不信你就貼一下試試**。


**此時我就發現一個絕佳的大廠面試題**，第一道題就是單純的爬樓梯，然後看候選人的程式碼實作，如果把 `dp[0]` 定義成 1 了，就可以發難了，為什麼 `dp[0]` 一定要初始化為 1，此時可能候選人就要強行給 `dp[0]` 應該是 1 找各種理由。那這就是一個考察點了，對 `dp[i]` 的定義理解得不深入。

然後可以繼續發難，如果一步一個台階、兩個台階、三個台階，直到 m 個台階，有多少種方法爬到 n 階樓頂。這道題目 LeetCode 上並沒有原題，絕對是考察候選人演算法能力的絕佳好題。

這一連套問下來，候選人演算法能力如何，面試官心裡就有數了。

**其實大廠面試最喜歡問的就是這種簡單題，然後慢慢變化，在小細節上考察候選人**。

這道絕佳的面試題我沒有用過，如果錄友們有面試別人的需求，就把這個固定做法拿去吧。

我在[通過一道面試題目，講一講遞歸算法的時間複雜度！](../前序/遞迴演算法的時間複雜性.md)中，以我自己面試別人的真實經歷，透過求 x 的 n 次方這麼簡單的題目，就可以考察候選人對演算法效能以及遞迴（recursion）的理解深度，錄友們可以看看，絕對有收穫！

## 週四

這道題目[動态规劃：使用最小花費爬樓梯](https://programmercarl.com/0746.使用最小花费爬楼梯.html)就是在爬台階的基礎上加了一個花費，

這道題描述也確實有點魔幻。

題目描述為：每當你爬上一個階梯你都要花費對應的體力值，一旦支付了相應的體力值，你就可以選擇向上爬一個階梯或者爬兩個階梯。

範例 1：

輸入：`cost = [10, 15, 20]`
輸出：`15`


**從題目描述可以看出：要不是第一步不需要花費體力，要不就是最後一步不需要花費體力，我個人理解：題意說的其實是第一步是要支付費用的！**因為是當你爬上一個台階就要花費對應的體力值！

所以我定義的 `dp[i]` 意思也是第一步是要花費體力的，最後一步不用花費體力了，因為已經支付了。

之後一些錄友在留言區說可以定義 `dp[i]` 為：第一步是不花費體力，最後一步是花費體力的。

所以程式碼也可以這麼寫：

```CPP
class Solution {
public:
    int minCostClimbingStairs(vector<int>& cost) {
        vector<int> dp(cost.size() + 1);
        dp[0] = 0; // 預設第一步都是不花費體力的
        dp[1] = 0;
        for (int i = 2; i <= cost.size(); i++) {
            dp[i] = min(dp[i - 1] + cost[i - 1], dp[i - 2] + cost[i - 2]);
        }
        return dp[cost.size()];
    }
};
```

這麼寫看上去比較順，但是就是感覺和題目描述的不太符。也沒有必要這麼細究題意了，大家只要知道，題目的意思反正就是要不是第一步不花費，要不是最後一步不花費，都可以。
