
# 本週小結！（回溯演算法系列二）

> 例行每週小結

## 週一

在[回溯算法：求組合總和（二）](https://programmercarl.com/0039.组合总和.html)中講解的組合（combination）總和問題，和以前的組合問題還都不一樣。

本題和[回溯算法：求組合問題！](https://programmercarl.com/0077.组合.html)，[回溯算法：求組合總和！](https://programmercarl.com/0216.组合总和III.html)的區別是：本題沒有數量要求，可以無限重複（duplicate），但是有總和的限制，所以間接也是有個數的限制。

不少錄友都是看到可以重複選擇，就義無反顧地把 `startIndex` 去掉了。

**本題還需要 `startIndex` 來控制 for 迴圈（for-loop）的起始位置，對於組合問題，什麼時候需要 `startIndex` 呢？**

我舉過例子，如果是一個集合（set）來求組合的話，就需要 `startIndex`，例如：[回溯算法：求組合問題！](https://programmercarl.com/0077.组合.html)，[回溯算法：求組合總和！](https://programmercarl.com/0216.组合总和III.html)。

如果是多個集合取組合，各個集合之間相互不影響，那麼就不用 `startIndex`，例如：[回溯算法：電話號碼的字母組合](https://programmercarl.com/0017.电话号码的字母组合.html)

**注意以上我只是說求組合的情況，如果是排列（permutation）問題，又是另一套分析的固定做法，後面我在講解排列的時候會重點介紹**。

最後還給出了本題的修剪法（pruning）最佳化，如下：

```
for (int i = startIndex; i < candidates.size() && sum + candidates[i] <= target; i++)
```

這個最佳化如果是初學者的話並不容易想到。

**在求和問題中，排序（sorting）之後加剪枝是常見的固定做法！**

在[回溯算法：求組合總和（二）](https://programmercarl.com/0039.组合总和.html)第一個樹狀結構（tree structure）沒有畫出 `startIndex` 的作用，**這裡糾正一下，準確的樹狀結構如圖所示：**

## 週二

在[回溯算法：求組合總和（三）](https://programmercarl.com/0040.组合总和II.html)中依舊講解組合總和問題，本題集合元素（element）會有重複，但要求 solution set 不能包含重複的組合。

**所以難就難在去重問題上了**。

這個去重問題，相信做過的錄友都知道有多麼的晦澀難懂。網路上的題解一般就說「去掉重複」，但說不清怎麼個去重，程式碼一甩就完事了。

為了講解這個去重問題，**我自創了兩個詞彙，「樹枝去重」和「樹層去重」**。

都知道組合問題可以抽象為樹狀結構，那麼「使用過」在這個樹狀結構上是有兩個維度的，一個維度是同一樹枝上「使用過」，一個維度是同一樹層上「使用過」。**沒有理解這兩個層面上的「使用過」是造成大家沒有徹底理解去重的根本原因**。

![40.組合總和II1](https://file1.kamacoder.com/i/algo/20201123202817973.png)

我在圖中將 `used` 的變化用橘黃色標註上，可以看出在 `candidates[i] == candidates[i - 1]` 相同的情況下：

* `used[i - 1] == true`，說明同一樹枝 `candidates[i - 1]` 使用過
* `used[i - 1] == false`，說明同一樹層 `candidates[i - 1]` 使用過

**這塊去重的邏輯很抽象，網路上搜尋的題解基本沒有能講清楚的，如果大家之前思考過這個問題或者刷過這道題目，看到這裡一定會感覺通透了很多！**

對於去重，其實排列問題也是一樣的道理，後面我會講到。


## 週三

在[回溯算法：分割回文串](https://programmercarl.com/0131.分割回文串.html)中，我們開始講解切割問題，雖然最後程式碼看起來好像是一道模板（template）題，但是從分析到學會套用這個模板，是比較難的。

我列出如下幾個難點：

* 切割問題其實類似組合問題
* 如何模擬（simulation）那些切割線
* 切割問題中遞迴（recursion）如何終止
* 在遞迴迴圈（loop）中如何截取子字串（substring）
* 如何判斷回文（palindrome）

如果想到**用求解組合問題的解題思路來解決切割問題，本題就成功一大半了**，接下來就可以對著模板照葫蘆畫瓢。

**但後續如何模擬切割線，如何終止，如何截取子字串，其實都不好想，最後判斷回文算是最簡單的了**。

除了這些難點，**本題還有細節，例如：切割過的地方不能重複切割，所以遞迴函數（recursive function）需要傳入 `i + 1`**。

所以本題應該是一道 hard 題目了。

**本題的樹狀結構中，和程式碼的邏輯有一個小出入，已經判斷不是回文的子字串就不會進入遞迴了，糾正如下：**

## 週四

如果沒有做過[回溯算法：分割回文串](https://programmercarl.com/0131.分割回文串.html)的話，[回溯算法：複原IP地址](https://programmercarl.com/0093.复原IP地址.html)這道題目應該是比較難的。

復原 IP 照[回溯算法：分割回文串](https://programmercarl.com/0131.分割回文串.html)就多了一些限制，例如只能分四段，而且還是更改字串（string），插入逗點。

樹形圖如下：

![93.複原IP地址](https://file1.kamacoder.com/i/algo/20201123203735933-20230310133532452.png)

在本文的樹狀結構圖中，我已經把詳細的分析思路都畫了出來，相信大家看了之後一定會思路清晰不少！

本題還可以有一個剪枝，合法 IP 長度為 12，如果 `s` 的長度超過了 12 就不是有效 IP 位址（address），直接回傳！

程式碼如下：

```
if (s.size() > 12) return result; // 修剪

```

我之前給出的 C++ 程式碼沒有加這個限制，也沒有逾時，因為在第四段超過長度之後，就會截止了，所以就算給出特別長的字串，搜尋的範圍也是有限的（遞迴只會到第三層），及時就會回傳了。


## 週五

在[回溯算法：求子集問題！](https://programmercarl.com/0078.子集.html)中講解了子集（subset）問題，**在樹狀結構中子集問題是要收集所有節點（node）的結果，而組合問題是收集葉節點（leaf node）的結果**。

如圖：

![78.子集](https://file1.kamacoder.com/i/algo/202011232041348.png)


認清這個本質之後，今天的題目就是一道模板題了。

其實可以不需要加終止條件（termination condition），因為 `startIndex >= nums.size()`，本層 for 迴圈本來也結束了，本來我們就要遍歷（traversal）整棵樹（tree）。

有的同學可能擔心不寫終止條件會不會無限遞迴（infinite recursion）？

並不會，因為每次遞迴的下一層就是從 `i+1` 開始的。

如果要寫終止條件，注意：`result.push_back(path);` 要放在終止條件的上面，如下：

```
result.push_back(path); // 收集子集，要放在終止條件的上面，否則會漏掉自己
if (startIndex >= nums.size()) { // 終止條件可以不加
    return;
}
```

本週我們依次介紹了組合問題、分割問題以及子集問題，子集問題還沒有講完，下週還會繼續。

還有一些錄友會很關心 LeetCode 上的耗時統計。

這個是很不準確的，相同的程式碼多提交幾次，大家就知道怎麼回事了。

LeetCode 上的計時應該是以 4ms 為單位，有的多提交幾次，多個 4ms 就多擊敗 50%，所以比較誇張，如果程式執行是幾百 ms 的級別，可以看看 LeetCode 上的耗時，因為它的誤差十幾 ms 對最終影響不大。

**所以我的題解基本不會寫擊敗百分之多少多少，沒啥意義，時間複雜性（time complexity）分析清楚了就可以了**，至於回溯演算法不用分析時間複雜性了，都是一樣的暴力搜尋，就看誰剪枝厲害了。
