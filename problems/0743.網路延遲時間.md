# 743. 網路延遲時間

https://leetcode.cn/problems/network-delay-time/description/ 


有 n 個網路節點（node），標記為 1 到 n。

給你一個列表 times，表示訊號經過有向邊（edge）的傳遞時間。times[i] = (ui, vi, wi)，其中 ui 是源節點，vi 是目標節點，wi 是一個訊號從源節點傳遞到目標節點的時間。

現在，從某個節點 K 發出一個訊號。需要多久才能使所有節點都收到訊號？如果不能使所有節點收到訊號，回傳 -1。

![](https://file1.kamacoder.com/i/algo/20240229104105.png)

提示：

* 1 <= k <= n <= 100
* 1 <= times.length <= 6000
* times[i].length == 3
* 1 <= ui, vi <= n
* ui != vi
* 0 <= wi <= 100
* 所有 (ui, vi) 對都互不相同（即不含重複邊）

# Dijkstra 精講

本題就是求最短路徑（shortest path），最短路徑是圖論（graph theory）中的經典問題，即：給出一個有向圖（directed graph），一個起點，一個終點，問起點到終點的最短路徑。

接下來，我們來詳細講解最短路徑演算法中的 Dijkstra 演算法（Dijkstra algorithm）。

Dijkstra 演算法：在加權圖形（weighted graph）（權值非負數）中求從起點到其他節點的最短路徑演算法。

需要注意兩點：

* Dijkstra 演算法可以同時求起點到所有節點的最短路徑
* 權值不能為負數

（這兩點後面我們會講到）

如本題範例中的圖：

![](https://file1.kamacoder.com/i/algo/20240125162647.png)

起點（節點 1）到終點（節點 7）的最短路徑是圖中標記綠線的部分。

最短路徑的權值為 12。

其實 Dijkstra 演算法和我們之前講解的 Prim 的最小生成樹演算法（Prim's algorithm）想法非常接近，如果大家認真學過 [Prim 演算法](https://mp.weixin.qq.com/s/yX936hHC6Z10K36Vm1Wl9w)，那麼理解 Dijkstra 演算法會相對容易很多。（這也是我要先講 Prim 再講 Dijkstra 的原因）

Dijkstra 演算法同樣是貪心法（greedy）的想法，不斷尋找距離源點最近的沒有訪問過的節點。

這裡我也給出 **Dijkstra 三部曲**：

1. 第一步，選源點到哪個節點近且該節點未被訪問過
2. 第二步，該最近節點被標記訪問過
3. 第三步，更新非訪問節點到源點的距離（即更新 minDist 陣列（array））

大家此時已經會發現，這和 Prim 演算法怎麼這麼像呢。

我在 [Prim 演算法](https://mp.weixin.qq.com/s/yX936hHC6Z10K36Vm1Wl9w)講解中也給出了三部曲。Prim 和 Dijkstra 確實很像，想法也是類似的，這一點我在後面還會詳細來講。

在 Dijkstra 演算法中，同樣有一個陣列很重要，起名為：minDist。

**minDist 陣列用來記錄每一個節點距離源點的最小距離**。

理解這一點很重要，也是理解 Dijkstra 演算法的核心所在。

### 程式碼實作

本題程式碼如下，裡面的三部曲我都做了註解，大家按照我上面的講解來看如下程式碼：

```CPP 
class Solution {
public:
    int networkDelayTime(vector<vector<int>>& times, int n, int k) {

        // 注意題目中給的二維陣列並不是相鄰矩陣
        // 需要相鄰矩陣來存圖
        // 因為本題處理方式是節點標號從 1 開始，所以陣列的大小都是 n+1
        vector<vector<int>> grid(n + 1, vector<int>(n + 1, INT_MAX));
        for(int i = 0; i < times.size(); i++){
            int p1 = times[i][0];
            int p2 = times[i][1];
            grid[p1][p2] = times[i][2];
        }

        // 儲存從源點到每個節點的最短距離
        std::vector<int> minDist(n + 1, INT_MAX);  

        // 記錄頂點是否被訪問過
        std::vector<bool> visited(n + 1, false); 

        minDist[k] = 0;  // 起始點到自身的距離為 0
        for (int i = 1; i <= n; i++) {

            int minVal = INT_MAX;
            int cur = 1;

            // 遍歷每個節點，選擇未被訪問的節點集合中哪個節點到源點的距離最小
            for (int v = 1; v <= n; ++v) {
                if (!visited[v] && minDist[v] <= minVal) {
                    minVal = minDist[v];
                    cur = v;
                }
            }

            visited[cur] = true;  // 標記該頂點已被訪問

            for (int v = 1; v <= n; v++) {
                if (!visited[v] && grid[cur][v] != INT_MAX && minDist[cur] + grid[cur][v] < minDist[v]) {
                    minDist[v] = minDist[cur] + grid[cur][v];
                }
            }


        }
        // 源點到最遠的節點的時間，也就是尋找源點到所有節點最短路徑的最大值
        int result = 0;
        for (int i = 1; i <= n; i++) {
            if (minDist[i] == INT_MAX) return -1;// 沒有路徑
            result = max(minDist[i], result);
        }
        return result;

    }
};
```

* 時間複雜性（time complexity）：O(n^2)
* 空間複雜度（space complexity）：O(n^2)

## Dijkstra 與 Prim 演算法的區別

> 這裡再次提示，需要先看我的 [Prim 演算法精講](https://mp.weixin.qq.com/s/yX936hHC6Z10K36Vm1Wl9w)，否則可能不知道我下面講的是什麼。

大家可以發現 Dijkstra 的程式碼看上去怎麼和 Prim 演算法這麼像呢。

其實程式碼大體不差，唯一區別在三部曲中的第三步：更新 minDist 陣列

因為 **Prim 是求非訪問節點到最小生成樹（minimum spanning tree, MST）的最小距離，而 Dijkstra 是求非訪問節點到源點的最小距離**。

Prim 更新 minDist 陣列的寫法：


```CPP 
for (int j = 1; j <= v; j++) {
    if (!isInTree[j] && grid[cur][j] < minDist[j]) {
        minDist[j] = grid[cur][j];
    }
}
```

因為 minDist 表示節點到最小生成樹的最小距離，所以新節點 cur 的加入，只需要使用 grid[cur][j]，grid[cur][j] 就表示 cur 加入生成樹後，生成樹到節點 j 的距離。

Dijkstra 更新 minDist 陣列的寫法：

```CPP 
for (int v = 1; v <= n; v++) {
    if (!visited[v] && grid[cur][v] != INT_MAX && minDist[cur] + grid[cur][v] < minDist[v]) {
        minDist[v] = minDist[cur] + grid[cur][v];
    }
}
```

因為 minDist 表示節點到源點的最小距離，所以新節點 cur 的加入，需要使用源點到 cur 的距離（minDist[cur]）+ cur 到節點 v 的距離（grid[cur][v]），才是源點到節點 v 的距離。

此時大家可能不禁要想，Prim 演算法可以有負權值嗎？

當然可以！

讀者／錄友們可以自己思考一下，這是為什麼？

這裡我提示一下：Prim 演算法只需要將節點以最小權值和連結在一起，不涉及到單一路徑。

## 堆積（heap）最佳化版本 Dijkstra

> 本篇我們來講解堆積最佳化版 Dijkstra，看本篇之前，一定要先看我講解的樸素版 Dijkstra，否則本篇會有部分內容看不懂。

在上一篇中，我們講解了樸素版的 Dijkstra，該解法的時間複雜性為 O(n^2)，可以看出時間複雜性只和 n（節點數量）有關係。

如果 n 很大的話，我們可以換一個角度來最佳化效能。

在講解最小生成樹的時候，我們講了兩個演算法，[Prim 演算法](https://mp.weixin.qq.com/s/yX936hHC6Z10K36Vm1Wl9w)（從點的角度來求最小生成樹）、[Kruskal 演算法（Kruskal's algorithm）](https://mp.weixin.qq.com/s/rUVaBjCES_4eSjngceT5bw)（從邊的角度來求最小生成樹）

那麼在 n 很大的時候，也有另一個思考維度，即：從邊的數量出發。

當 n 很大，邊的數量也很多的時候（dense graph），那麼上述解法沒問題。

但 n 很大，邊的數量很小的時候（sparse graph），是不是可以換成從邊的角度來求最短路徑呢？

畢竟邊的數量少。

有的讀者／錄友可能會想，n（節點數量）很大，邊不就多嗎？怎麼會邊的數量少呢？

別忘了，誰也沒有規定節點之間一定要有邊連接著，例如有一萬個節點，只有一條邊，這也是一張圖。

了解背景之後，再來看解法想法。

### 圖（graph）的儲存

首先是圖的儲存。

關於圖的儲存，主流有兩種方式：相鄰矩陣（adjacency matrix）和相鄰串列（adjacency list）

#### 相鄰矩陣

相鄰矩陣使用二維（2D）陣列來表示圖結構。相鄰矩陣是從節點的角度來表示圖，有多少節點就申請多大的二維陣列。

例如：grid[2][5] = 6，表示節點 2 連結節點 5 為有向圖，節點 2 指向節點 5，邊的權值為 6（套在題意裡，可能是距離為 6 或者消耗為 6 等等）

如果想表示無向圖（undirected graph），即：grid[2][5] = 6，grid[5][2] = 6，表示節點 2 與節點 5 相互連通，權值為 6。


如圖：

![](https://file1.kamacoder.com/i/algo/20240222110025.png)

在一個 n（節點數）為 8 的圖中，就需要申請 8 * 8 這麼大的空間，有一條雙向邊，即：grid[2][5] = 6，grid[5][2] = 6

這種表達方式（相鄰矩陣）在邊少、節點多的情況下，會導致申請過大的二維陣列，造成空間浪費。

而且在尋找節點連結情況的時候，需要遍歷（traversal）整個矩陣，即 n * n 的時間複雜性，同樣造成時間浪費。

相鄰矩陣的優點：

* 表達方式簡單，易於理解
* 檢查任意兩個頂點（vertex）間是否存在邊的操作非常快
* 適合 dense graph，在邊數接近頂點數平方的圖中，相鄰矩陣是一種空間效率較高的表示方法。

缺點：

* 遇到 sparse graph，會導致申請過大的二維陣列造成空間浪費，且遍歷邊的時候需要遍歷整個 n * n 矩陣，造成時間浪費

#### 相鄰串列

相鄰串列使用陣列 + 鏈接串列（linked list）的方式來表示。相鄰串列是從邊的數量來表示圖，有多少邊才會申請對應大小的鏈接串列。

相鄰串列的建構如圖：

![](https://file1.kamacoder.com/i/algo/20240223103713.png)

這裡表達的圖是：

* 節點 1 指向節點 3 和節點 5
* 節點 2 指向節點 4、節點 3、節點 5
* 節點 3 指向節點 4，節點 4 指向節點 1。

有多少邊，相鄰串列才會申請多少個對應的鏈接串列節點。

從圖中可以直觀看出使用陣列 + 鏈接串列來表達邊的連結情況。

相鄰串列的優點：

* 對於 sparse graph 的儲存，只需要儲存邊，空間利用率高
* 遍歷節點連結情況相對容易

缺點：

* 檢查任意兩個節點間是否存在邊，效率相對低，需要 O(V) 時間，V 表示某節點連結其他節點的數量。
* 實作相對複雜，不易理解

#### 本題圖的儲存

接下來我們繼續按照 sparse graph 的角度來分析本題。

在第一個版本的實作想法中，我們提到了三部曲：

1. 第一步，選源點到哪個節點近且該節點未被訪問過
2. 第二步，該最近節點被標記訪問過
3. 第三步，更新非訪問節點到源點的距離（即更新 minDist 陣列）

在第一個版本的程式碼中，這三部曲是套在一個 for 迴圈（for-loop）裡，為什麼？

因為我們是從節點的角度來解決問題。

三部曲中第一步（選源點到哪個節點近且該節點未被訪問過），這個操作本身需要 for 迴圈遍歷 minDist 來尋找最近的節點。

同時我們需要遍歷所有未訪問過的節點，所以我們從節點角度出發，程式碼會有兩層 for 迴圈，程式碼是這樣的：（注意程式碼中的註解，標記兩層 for 迴圈的用處）

```CPP 

for (int i = 1; i <= n; i++) { // 遍歷所有節點，第一層 for 迴圈

    int minVal = INT_MAX;
    int cur = 1;

    // 1、選距離源點最近且未訪問過的節點，第二層 for 迴圈
    for (int v = 1; v <= n; ++v) {
        if (!visited[v] && minDist[v] < minVal) {
            minVal = minDist[v];
            cur = v;
        }
    }

    visited[cur] = true;  // 2、標記該節點已被訪問

    // 3、第三步，更新非訪問節點到源點的距離（即更新 minDist 陣列）
    for (int v = 1; v <= n; v++) {
        if (!visited[v] && grid[cur][v] != INT_MAX && minDist[cur] + grid[cur][v] < minDist[v]) {
            minDist[v] = minDist[cur] + grid[cur][v];
        }
    }

}
```

那麼當從邊的角度出發，在處理三部曲裡的第一步（選源點到哪個節點近且該節點未被訪問過）的時候，我們可以不用去遍歷所有節點了。

而且直接把邊（帶權值）加入到最小堆積（min heap）（利用堆積來自動排序），那麼每次我們從堆積頂裡取出邊自然就是距離源點最近的節點所在的邊。

這樣我們就不需要兩層 for 迴圈來尋找最近的節點了。

了解了大體想法，我們再來看程式碼實作。

首先是如何使用相鄰串列來表述圖結構，這是擺在很多讀者／錄友面前的第一個難題。

相鄰串列用陣列 + 鏈接串列來表示，程式碼如下：（C++ 中 vector 為陣列，list 為鏈接串列，定義了 n+1 這麼大的陣列空間）

```CPP 
vector<list<int>> grid(n + 1);
```

不少讀者／錄友不知道如何定義資料結構（data structure）、怎麼表示相鄰串列，我來給大家畫一個圖：

![](https://file1.kamacoder.com/i/algo/20240223103713.png)

圖中相鄰串列表示：

* 節點 1 指向節點 3 和節點 5
* 節點 2 指向節點 4、節點 3、節點 5
* 節點 3 指向節點 4
* 節點 4 指向節點 1

大家發現圖中的邊沒有權值，而本題中我們的邊是有權值的，權值怎麼表示？在哪裡表示？

所以在 `vector<list<int>> grid(n + 1);` 中就不能使用 int 了，而是需要一個鍵值對（key-value pair）來存兩個數字，一個數表示節點，一個數表示指向該節點的這條邊的權值。

那麼程式碼可以改成這樣：（pair 為鍵值對，可以存放兩個 int）

```CPP 
vector<list<pair<int,int>>> grid(n + 1);
```

舉例來給大家展示該程式碼表達的資料如下：

![](https://file1.kamacoder.com/i/algo/20240223103904.png)

* 節點 1 指向節點 3 權值為 1
* 節點 1 指向節點 5 權值為 2
* 節點 2 指向節點 4 權值為 7
* 節點 2 指向節點 3 權值為 6
* 節點 2 指向節點 5 權值為 3
* 節點 3 指向節點 4 權值為 3
* 節點 5 指向節點 1 權值為 10

這樣我們就把圖中權值表示出來了。

但是在程式碼中使用 `pair<int, int>` 很容易讓我們搞混，第一個 int 表示什麼，第二個 int 表示什麼，導致程式碼可讀性（readability）很差，或者說別人看你的程式碼看不懂。

那麼可以定義一個類別（class）來取代 `pair<int, int>`

類別（或者說是 struct）定義如下：

```CPP
struct Edge {
    int to;  // 相鄰頂點
    int val; // 邊的權重

    Edge(int t, int w): to(t), val(w) {}  // 建構函式
};
```

這個類別裡有兩個成員變數，有對應的命名，這樣不容易搞混兩個 int 的含義。

所以本題中相鄰串列的定義如下：

```CPP 
struct Edge {
    int to;  // 連結的節點
    int val; // 邊的權重

    Edge(int t, int w): to(t), val(w) {}  // 建構函式
};

vector<list<Edge>> grid(n + 1); // 相鄰串列

```

（我們在下面的講解中會直接使用這個相鄰串列的程式碼表示方式）

### 堆積最佳化細節

其實想法依然是 Dijkstra 三部曲：

1. 第一步，選源點到哪個節點近且該節點未被訪問過
2. 第二步，該最近節點被標記訪問過
3. 第三步，更新非訪問節點到源點的距離（即更新 minDist 陣列）

只不過之前是透過遍歷節點來遍歷邊，透過兩層 for 迴圈來尋找距離源點最近節點。這次我們直接遍歷邊，且透過堆積來對邊進行排序，達到直接選擇距離源點最近節點。

先來看一下針對這三部曲，如果用堆積來最佳化。

那麼三部曲中的第一步（選源點到哪個節點近且該節點未被訪問過），我們如何選？

我們要選擇距離源點近的節點（即：該邊的權值最小），所以我們需要一個最小堆積來幫我們對邊的權值排序，每次從最小堆積頂取邊就是權值最小的邊。

C++ 定義最小堆積，可以用優先佇列（priority queue）實作，程式碼如下：

```CPP 
// 最小堆積
class mycomparison {
public:
    bool operator()(const pair<int, int>& lhs, const pair<int, int>& rhs) {
        return lhs.second > rhs.second;
    }
};
// 優先佇列中存放 pair<節點編號，源點到該節點的權值>
priority_queue<pair<int, int>, vector<pair<int, int>>, mycomparison> pq;
```

（`pair<int, int>` 中第二個 int 為什麼要存源點到該節點的權值，因為這個最小堆積需要按照權值來排序）


有了最小堆積自動對邊的權值排序，那我們只需要直接從堆積裡取堆積頂元素（element）（最小堆積中，最小的權值在上面），就可以取到離源點最近的節點了（未訪問過的節點，不會加到堆積裡進行排序）

所以三部曲中的第一步，我們不用 for 迴圈去遍歷，直接取堆積頂元素：

```CPP 
// pair<節點編號，源點到該節點的權值>
pair<int, int> cur = pq.top(); pq.pop();

```

第二步（該最近節點被標記訪問過）這個就是將節點做訪問標記，和樸素 Dijkstra 一樣，程式碼如下：

```CPP 
// 2. 第二步，該最近節點被標記訪問過
visited[cur.first] = true;

```

（`cur.first` 是指取 `pair<int, int>` 裡的第一個 int，即節點編號）

第三步（更新非訪問節點到源點的距離），這裡的想法也是和樸素 Dijkstra 一樣的。

但很多讀者／錄友對這裡是最懵的，主要是因為兩點：

* 沒有理解透徹 Dijkstra 的想法
* 沒有理解相鄰串列的表達方式

我們來回顧一下樸素 Dijkstra 在這一步的程式碼和想法（如果沒看過我講解的樸素版 Dijkstra，這裡會看不懂）

```CPP 

// 3、第三步，更新非訪問節點到源點的距離（即更新 minDist 陣列）
for (int v = 1; v <= n; v++) {
    if (!visited[v] && grid[cur][v] != INT_MAX && minDist[cur] + grid[cur][v] < minDist[v]) {
        minDist[v] = minDist[cur] + grid[cur][v];
    }
}
```

其中 for 迴圈是用來做什麼的？是為了找到節點 cur 連結指向了哪些節點，因為使用相鄰矩陣的表達方式，所以把所有節點遍歷一遍。

而在相鄰串列中，我們可以以相對高效的方式知道一個節點連結指向哪些節點。

再回顧一下相鄰串列的建構（陣列 + 鏈接串列）：

![](https://file1.kamacoder.com/i/algo/20240223103713.png)

假如加入的 cur 是節點 2，那麼 grid[2] 表示的就是圖中第二行鏈接串列。（grid 陣列的建構我們在上面「圖的儲存」中講過）

所以在相鄰串列中，我們要獲取節點 cur 連結指向哪些節點，就是遍歷 grid[cur節點編號] 這個鏈接串列。

這個遍歷方式，C++ 程式碼如下：

```CPP 
for (Edge edge : grid[cur.first]) 
```

（如果不知道 Edge 是什麼，看上面「圖的儲存」中相鄰串列的講解）

`cur.first` 就是 cur 節點編號，參考上面 pair 的定義：pair<節點編號，源點到該節點的權值>

接下來就是更新非訪問節點到源點的距離，程式碼實作和樸素 Dijkstra 是一樣的，程式碼如下：

```CPP 
// 3. 第三步，更新非訪問節點到源點的距離（即更新 minDist 陣列）
for (Edge edge : grid[cur.first]) { // 遍歷 cur 指向的節點，cur 指向的節點為 edge
    // cur 指向的節點 edge.to，這條邊的權值為 edge.val
    if (!visited[edge.to] && minDist[cur.first] + edge.val < minDist[edge.to]) { // 更新 minDist
        minDist[edge.to] = minDist[cur.first] + edge.val;
        pq.push(pair<int, int>(edge.to, minDist[edge.to]));
    }
}
```

但為什麼想法一樣，有的讀者／錄友能寫出樸素 Dijkstra，但堆積最佳化這裡的邏輯就是寫不出來呢？

**主要就是因為對相鄰串列的表達方式不熟悉**！

以上程式碼中，cur 連結指向的節點編號為 edge.to，這條邊的權值為 edge.val，如果對這裡模糊的就再回顧一下 Edge 的定義：

```CPP 
struct Edge {
    int to;  // 相鄰頂點
    int val; // 邊的權重

    Edge(int t, int w): to(t), val(w) {}  // 建構函式
};
```

確定該節點沒有被訪問過，`!visited[edge.to]`，目前源點到 cur.first 的最短距離（minDist）+ cur.first 到 edge.to 的距離（edge.val）是否小於 minDist 已經記錄的源點到 edge.to 的距離（minDist[edge.to]）

如果是的話，就開始更新操作。

即：

```CPP 
if (!visited[edge.to] && minDist[cur.first] + edge.val < minDist[edge.to]) { // 更新 minDist
    minDist[edge.to] = minDist[cur.first] + edge.val;
    pq.push(pair<int, int>(edge.to, minDist[edge.to])); // 由於 cur 節點的加入，而新連結的邊，加入到優先佇列中
}

```

同時，由於 cur 節點的加入，源點又有可以新連結到的邊，將這些邊加入到優先佇列中。


以上程式碼想法和樸素版 Dijkstra 是一模一樣的，主要區別是兩點：

* 相鄰串列的表示方式不同
* 使用優先佇列（最小堆積）來對新連結的邊排序

### 程式碼實作

堆積最佳化 Dijkstra 完整程式碼如下：

```CPP
class Solution {
public:
    // 最小堆積
    class mycomparison {
    public:
        bool operator()(const pair<int, int>& lhs, const pair<int, int>& rhs) {
            return lhs.second > rhs.second;
        }
    };
    // 定義一個 struct 來表示帶權重的邊
    struct Edge {
        int to;  // 相鄰頂點
        int val; // 邊的權重

        Edge(int t, int w): to(t), val(w) {}  // 建構函式
    };
    int networkDelayTime(vector<vector<int>>& times, int n, int k) {


        std::vector<std::list<Edge>> grid(n + 1);
        for(int i = 0; i < times.size(); i++){
            int p1 = times[i][0];
            int p2 = times[i][1];
            // p1 指向 p2，權值為 times[i][2]
            grid[p1].push_back(Edge(p2, times[i][2]));
        }

        // 儲存從源點到每個節點的最短距離
        std::vector<int> minDist(n + 1, INT_MAX);

        // 記錄頂點是否被訪問過
        std::vector<bool> visited(n + 1, false);

        // 優先佇列中存放 pair<節點，源點到該節點的距離>
        priority_queue<pair<int, int>, vector<pair<int, int>>, mycomparison> pq;

        pq.push(pair<int, int>(k, 0));
        minDist[k] = 0; // 這個不要忘了

        while (!pq.empty()) {
            // <節點，源點到該節點的距離>
            // 1. 第一步，選源點到哪個節點近且該節點未被訪問過（透過優先佇列來實作）
            pair<int, int> cur = pq.top(); pq.pop();

            if (visited[cur.first]) continue;

            // 2. 第二步，該最近節點被標記訪問過
            visited[cur.first] = true;


            // 3. 第三步，更新非訪問節點到源點的距離（即更新 minDist 陣列）
            for (Edge edge : grid[cur.first]) { // 遍歷 cur 指向的節點，cur 指向的節點為 edge
                // cur 指向的節點 edge.to，這條邊的權值為 edge.val
                if (!visited[edge.to] && minDist[cur.first] + edge.val < minDist[edge.to]) { // 更新 minDist
                    minDist[edge.to] = minDist[cur.first] + edge.val;
                    pq.push(pair<int, int>(edge.to, minDist[edge.to]));
                }
            }

        }

        // 源點到最遠的節點的時間，也就是尋找源點到所有節點最短路徑的最大值
        int result = 0;
        for (int i = 1; i <= n; i++) {
            if (minDist[i] == INT_MAX) return -1;// 沒有路徑
            result = max(minDist[i], result);
        }
        return result;

    }
};

```

* 時間複雜性：O(ElogE) E 為邊的數量
* 空間複雜度：O(N + E) N 為節點的數量

堆積最佳化的時間複雜性只和邊的數量有關，和節點數無關，在優先佇列中放的也是邊。

以上程式碼中，`while (!pq.empty())` 裡套了 `for (Edge edge : grid[cur.first])`

`for` 裡遍歷的是當前節點 cur 所連接的邊。

那當前節點 cur 所連接的邊也是不固定的，這就讓大家分不清這時間複雜性究竟是多少？

其實 `for (Edge edge : grid[cur.first])` 裡最終的資料走向是給佇列裡添加邊。

那麼跳出局部程式碼，整個佇列一定是所有邊添加了一次，同時也彈出了一次。

所以邊添加一次時間複雜性是 O(E)，`while (!pq.empty())` 裡每次都要彈出一個邊來進行操作，在優先佇列（最小堆積）中彈出一個元素的時間複雜性是 O(logE)，這是錐形排序法（heap sort）的時間複雜性。

（當然最小堆積裡是添加元素的時候排序，還是取出元素的時候排序，這個無所謂，時間複雜性都是 O(E)，總之是一定要排序的，而最小堆積裡也不會滯留元素，有多少元素添加一定就有多少元素彈出）

所以該演算法整體時間複雜性為 O(ElogE)

網上的不少分析會把 n（節點的數量）算進來，這個分析是有問題的，舉一個極端例子，在 n 為 10000，且只有一條邊的圖裡，以上程式碼，大家感覺執行了多少次？

`while (!pq.empty())` 中的 pq 存的是邊，其實只執行了一次。

所以該演算法時間複雜性和節點沒有關係。

至於空間複雜度，相鄰串列是陣列 + 鏈接串列，陣列的空間是 N，有 E 條邊就申請對應多少個鏈接串列節點，所以複雜度是 N + E

## 拓展

當然也有讀者／錄友可能想，堆積最佳化 Dijkstra 中我為什麼一定要用相鄰串列呢，我就用相鄰矩陣行不行？

也行的。

但正是因為 sparse graph，所以我們使用堆積最佳化的想法，如果我們還用相鄰矩陣去表達這個圖的話，就是一個高效的演算法使用了低效的資料結構，那麼整體演算法效率依然是低的。

如果還不清楚為什麼要使用相鄰串列，可以再看看上面我在「圖的儲存」標題下的講解。

這裡我也給出相鄰矩陣版本的堆積最佳化 Dijkstra 程式碼：

```CPP
class Solution {
public:
    // 最小堆積（按照 <k ,v> 中的 v 來從小到大排序）
    class mycomparison {
    public:
        bool operator()(const pair<int, int>& lhs, const pair<int, int>& rhs) {
            return lhs.second > rhs.second;
        }
    };
    int networkDelayTime(vector<vector<int>>& times, int n, int k) {

        // 注意題目中給的二維陣列並不是相鄰矩陣
        // 需要相鄰矩陣來存圖
        // 因為本題處理方式是節點標號從 1 開始，所以陣列的大小都是 n+1
        vector<vector<int>> grid(n + 1, vector<int>(n + 1, INT_MAX));
        for(int i = 0; i < times.size(); i++){
            int p1 = times[i][0];
            int p2 = times[i][1];
            grid[p1][p2] = times[i][2];
        }

        // 儲存從源點到每個節點的最短距離
        std::vector<int> minDist(n + 1, INT_MAX);

        // 記錄頂點是否被訪問過
        std::vector<bool> visited(n + 1, false);

        // 優先佇列中存放 [節點，源點到該節點的距離]
        priority_queue<pair<int, int>, vector<pair<int, int>>, mycomparison> pq;

        pq.push(pair<int, int>(k, 0));
        minDist[k] = 0; // 這個不要忘了

        while (!pq.empty()) {
            // <節點，源點到該節點的距離>
            // 1、選距離源點最近且未訪問過的節點
            pair<int, int> cur = pq.top(); pq.pop();

            if (visited[cur.first]) continue;

            // 2、標記該節點已被訪問
            visited[cur.first] = true;

            // 3、第三步，更新非訪問節點到源點的距離（即更新 minDist 陣列）
            // 遍歷 cur 可以連結的節點，更新 minDist[j]
            for (int j = 1; j <= n; j++) {
                if (!visited[j] && grid[cur.first][j] != INT_MAX && (minDist[cur.first] + grid[cur.first][j] < minDist[j])) {
                    minDist[j] = minDist[cur.first] + grid[cur.first][j];
                    pq.push(pair<int, int>(j, minDist[j]));
                }
            }
        }

        // 源點到最遠的節點的時間，也就是尋找源點到所有節點最短路徑的最大值
        int result = 0;
        for (int i = 1; i <= n; i++) {
            if (minDist[i] == INT_MAX) return -1;// 沒有路徑
            result = max(minDist[i], result);
        }


        return result;

    }
};

```

* 時間複雜性：O(E * (N + logE)) E 為邊的數量，N 為節點數量
* 空間複雜度：O(log(N^2))

`while (!pq.empty())` 時間複雜性為 E，while 裡面每次取元素時間複雜性為 logE，和一個 for 迴圈時間複雜性為 N。

所以整體是 E * (N + logE)

很多讀者／錄友別說寫堆積最佳化，就是看堆積最佳化的程式碼也看得很懵。

這裡再給出本題的 Bellman_ford 解法，關於 Bellman_ford，後面我會專門來講解的，Bellman_ford 有其獨特的應用場景

```CPP 
class Solution {
public:

    int networkDelayTime(vector<vector<int>>& times, int n, int k) {
        vector<int> minDist(n + 1 , INT_MAX/2);
        minDist[k] = 0;
        //vector<int> minDist_copy(n); // 用來記錄每一次遍歷的結果
        for (int i = 1; i <= n + 1; i++) {
            //minDist_copy = minDist; // 獲取上一次計算的結果
            for (auto &f : times) {
                int from = f[0];
                int to = f[1];
                int price = f[2];
                if (minDist[to] > minDist[from] + price) minDist[to] = minDist[from] + price;
            }

        }
        int result = 0;
        for (int i = 1;i <= n; i++) {
            if (minDist[i] == INT_MAX/2) return -1;// 沒有路徑
            result = max(minDist[i], result);
        }
        return result;

    }
};
```
