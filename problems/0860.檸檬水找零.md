# 860.檸檬水找零

[LeetCode 題目連結](https://leetcode.com/problems/lemonade-change/)

在檸檬水攤上，每一杯檸檬水的售價為 5 美元。

顧客排隊購買你的產品，（按帳單 bills 支付的順序）一次購買一杯。

每位顧客只買一杯檸檬水，然後向你付 5 美元、10 美元或 20 美元。你必須給每個顧客正確找零，也就是說淨交易是每位顧客向你支付 5 美元。

注意，一開始你手頭沒有任何零錢。

如果你能給每位顧客正確找零，回傳 true ，否則回傳 false 。

範例 1：
* 輸入：[5,5,5,10,20]
* 輸出：true
* 解釋：
    * 前 3 位顧客那裡，我們按順序收取 3 張 5 美元的鈔票。
    * 第 4 位顧客那裡，我們收取一張 10 美元的鈔票，並返還 5 美元。
    * 第 5 位顧客那裡，我們找還一張 10 美元的鈔票和一張 5 美元的鈔票。
    * 由於所有客戶都得到了正確的找零，所以我們輸出 true。

範例 2：
* 輸入：[5,5,10]
* 輸出：true

範例 3：
* 輸入：[10,10]
* 輸出：false

範例 4：
* 輸入：[5,5,10,10,20]
* 輸出：false
* 解釋：
    * 前 2 位顧客那裡，我們按順序收取 2 張 5 美元的鈔票。
    * 對於接下來的 2 位顧客，我們收取一張 10 美元的鈔票，然後返還 5 美元。
    * 對於最後一位顧客，我們無法退回 15 美元，因為我們現在只有兩張 10 美元的鈔票。
    * 由於不是每位顧客都得到了正確的找零，所以答案是 false。

提示：

* 0 <= bills.length <= 10000
* bills[i] 不是 5 就是 10 或是 20

## 解題思路

這是前幾天的 LeetCode 每日一題，感覺不錯，給大家講一下。

這道題目剛一看，可能會有點懵，這要怎麼找零才能保證完成全部帳單的找零呢？

**但仔細一琢磨就會發現，可供我們做判斷的空間非常少！**

只需要維護三種金額的數量，5、10 和 20。

有如下三種情況：

* 情況一：帳單是 5，直接收下。
* 情況二：帳單是 10，消耗一個 5，增加一個 10
* 情況三：帳單是 20，優先消耗一個 10 和一個 5，如果不夠，再消耗三個 5

此時大家就發現情況一、情況二都是固定策略，都不用我們來做分析了，而唯一不確定的其實在情況三。

而情況三邏輯也不複雜甚至感覺純模擬（simulation）就可以了，其實情況三這裡是有貪心法（greedy）的。

帳單是 20 的情況，為什麼要優先消耗一個 10 和一個 5 呢？

**因為美元 10 只能給帳單 20 找零，而美元 5 可以給帳單 10 和帳單 20 找零，美元 5 更萬能！**

所以區域最佳（local optimum）：遇到帳單 20，優先消耗美元 10，完成本次找零。總體最佳（global optimum）：完成全部帳單的找零。

區域最佳可以推出總體最佳，並找不出反例，那麼就試試貪心演算法！

C++ 程式碼如下：

```CPP
class Solution {
public:
    bool lemonadeChange(vector<int>& bills) {
        int five = 0, ten = 0, twenty = 0;
        for (int bill : bills) {
            // 情況一
            if (bill == 5) five++;
            // 情況二
            if (bill == 10) {
                if (five <= 0) return false;
                ten++;
                five--;
            }
            // 情況三
            if (bill == 20) {
                // 優先消耗 10 美元，因為 5 美元的找零用處更大，能多留著就多留著
                if (five > 0 && ten > 0) {
                    five--;
                    ten--;
                    twenty++; // 其實這行程式碼可以刪了，因為記錄 20 已經沒有意義了，不會用 20 來找零
                } else if (five >= 3) {
                    five -= 3;
                    twenty++; // 同理，這行程式碼也可以刪了
                } else return false;
            }
        }
        return true;
    }
};
```
* 時間複雜度（time complexity）: O(n)
* 空間複雜度（space complexity）: O(1)


## 總結

乍眼一看好像很複雜，分析清楚之後，會發現邏輯其實非常固定。

這道題目可以告訴大家，遇到感覺沒有解題思路的題目，可以靜下心來把能遇到的情況分析一下，只要分析到具體情況了，一下子就豁然開朗了。

如果一直陷入想從整體上尋找找零方案，就會把自己陷進去，各種情況一交叉，只會越想越複雜了。

### C
```c
bool lemonadeChange(int* bills, int billsSize){
    // 分別記錄五元、十元的數量（二十元不用記錄，因為不會用到 20 元找零）
    int fiveCount = 0; int tenCount = 0; 

    int i;
    for(i = 0; i < billsSize; ++i) {
        // 分情況討論每位顧客的付款
        switch(bills[i]) {
            // 情況一：直接收款五元
            case 5:
                fiveCount++;
                break;
            // 情況二：收款十元
            case 10:
                // 若沒有五元找零，回傳 false
                if(fiveCount == 0)
                    return false;
                // 收款十元並找零五元
                fiveCount--;
                tenCount++;
                break;
            // 情況三：收款二十元
            case 20:
                // 若可以，優先用十元和五元找零（因為十元只能找零 20，所以需要盡量用掉。而 5 元能找零十元和二十元）
                if(fiveCount > 0 && tenCount > 0) {
                    fiveCount--;
                    tenCount--;
                } 
                // 若沒有十元，但是有三張五元。用三張五元找零
                else if(fiveCount >= 3) 
                    fiveCount-=3;
                // 無法找開，回傳 false
                else
                    return false;
                break;
        }
    }
    // 全部可以找開，回傳 true
    return true;
}
```
