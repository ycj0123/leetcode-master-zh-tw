什麼是空間複雜度呢？

是對一個演算法在執行過程中佔用記憶體（memory）空間大小的量度，記作 $S(n)=O(f(n))$。

空間複雜度（Space Complexity）記作 $S(n)$，依然使用大 O 記法（big O notation）來表示。利用程式的空間複雜度，可以對程式執行中需要多少記憶體有個預先估計。

關注空間複雜度有兩個常見的相關問題

1. 空間複雜度是考慮程式（可執行檔）的大小嗎？

很多同學都會混淆程式執行時記憶體大小和程式本身的大小。這裡強調一下**空間複雜度是考慮程式執行時佔用記憶體的大小，而不是可執行檔（executable file）的大小。**

2. 空間複雜度是準確算出程式執行時所佔用的記憶體嗎？

不要以為空間複雜度就已經精準地掌握了程式的記憶體使用大小，很多因素會影響程式真正記憶體使用大小，例如編譯器（compiler）的記憶體對齊（memory alignment），程式設計語言（programming language）容器（container）的底層實作等等這些都會影響到程式記憶體的開銷。

所以空間複雜度是預先大體評估程式記憶體使用的大小。

說到空間複雜度，我想同學們在 OJ（online judge）上應該遇到過這種錯誤，就是超出記憶體限制，一般 OJ 對程式執行時所消耗的記憶體都有一個限制。

為了避免記憶體超出限制，這也需要我們對演算法佔用多大的記憶體有一個大體的預估。

同樣在工程實踐中，電腦的記憶體空間也不是無限的，需要工程師對軟體執行時所使用的記憶體有一個大體評估，這都需要用到演算法空間複雜度的分析。

來看一下例子，什麼時候的空間複雜度是 $O(1)$ 呢，C++ 程式碼如下：

```CPP
int j = 0;
for (int i = 0; i < n; i++) {
    j++;
}

```
第一段程式碼可以看出，隨著 $n$ 的變化，所需開闢的記憶體空間並不會隨著 $n$ 的變化而變化。即此演算法空間複雜度為一個常數（constant），所以表示為大 $O(1)$。

什麼時候的空間複雜度是 $O(n)$？

當消耗空間和輸入參數（parameter）$n$ 保持線性增長，這樣的空間複雜度為 $O(n)$，來看一下這段 C++ 程式碼
```CPP
int* a = new int(n);
for (int i = 0; i < n; i++) {
    a[i] = i;
}
```

我們定義了一個陣列（array）出來，這個陣列佔用的大小為 $n$，雖然有一個 for 迴圈（for-loop），但沒有再分配新的空間，因此，這段程式碼的空間複雜度主要看第一行即可，隨著 $n$ 的增大，開闢的記憶體大小呈線性增長，即 $O(n)$。

其他的 $O(n^2)$，$O(n^3)$ 我想大家應該都可以以此類舉出來了，**那麼思考一下什麼時候空間複雜度是 $O(\log n)$ 呢？**

空間複雜度是 $\log n$ 的情況確實有些特殊，其實是在**遞迴（recursion）的時候，會出現空間複雜度為 $\log n$ 的情況**。
