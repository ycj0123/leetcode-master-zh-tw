
# 看了這麼多程式碼，談一談程式碼風格！

最近看了很多錄友在 [leetcode-master](https://mp.weixin.qq.com/s/wZRTrA9Rbvgq1yEkSw4vfQ) 上提交的程式碼，發現很多錄友的程式碼其實並不規範，這一點平時在交流群組和知識星球裡也能看出來。

很多錄友對程式碼規範應該了解得不多，程式碼看起來並不舒服。

所以呢，我給大家講一講程式碼規範，我主要以 C++ 程式碼為例。

需要強調一下，程式碼規範並不僅僅是讓程式碼看著舒服，這是一個很重要的習慣。

## 題外話

工作之後，**特別是在大型企業，看誰的技術厲不厲害，不用看誰寫出多厲害的程式碼，就程式碼風格掃一眼，立刻就能看出來是正規軍還是野生程式設計師（programmer）**。

很多人甚至不屑於了解程式碼規範，認為實作功能就行，這種觀點其實在上個世紀是很普遍的，因為那時候一般寫程式碼不需要合作，自己一個人寫整個專案，想怎麼寫就怎麼寫。

現在一些小公司，甚至大公司裡的某些技術團隊也不注重程式碼規範，趕進度做出功能就完事，這種情況就要分兩方面看：

* 第一種情況：這個專案在業務上具有巨大潛力，需要搶占市場，只要先站住市場就能賺到錢，每年年終好幾十萬，那專案前期還關心什麼程式碼風格，趕進度把功能做出來，賺錢就完事了，例如 2012 年的微信，2015 年的王者榮耀。這些專案都是後期再不斷最佳化的。

* 第二種情況：這個專案沒賺到錢，半死不活的，程式碼還沒有設計也沒有規範，這樣對技術人員的傷害就非常大了。

**而不注重程式碼風格的團隊，99.99% 都是第二種情況**，如果你趕上了第一種情況，那就恭喜你了，本文下面的內容可以不用看了。

## 程式碼規範

### 變數（variable）命名

這裡我簡單說一說規範問題。

**權威的 C++ 規範以 Google 為主**，我給大家下載了一份中文版本，在公眾號（WeChat Official Account）「代碼隨想錄」後台回覆：編程規範，就可以領取。

**具體的規範要以自己團隊風格為主**，融入團隊才是最重要的。

我先來說說變數的命名。

主流有如下三種變數規則：

* 小駝峰、大駝峰命名法（camel case）
* 底線命名法（snake case）
* 匈牙利命名法（Hungarian notation）

小駝峰，第一個單字首字母小寫，後面其他單字首字母大寫。例如 `int myAge;`

大駝峰法把第一個單字的首字母也大寫了。例如：``int MyAge;``

通常來講 Java 和 Go 都使用駝峰命名法，C++ 的函式（function）和結構（struct）命名也是用大駝峰，**大家可以看到題解中我的 C++ 程式碼風格就是小駝峰，因為 LeetCode 上給出的預設函式的命名就是小駝峰，所以我入鄉隨俗**。

底線命名法是名稱中的每一個邏輯斷點都用一個底線來標記，例如：`int my_age`，**底線命名法是隨著 C 語言的出現流行起來的，如果大家看過 UNIX 進階程式設計或者 UNIX 網路程式設計，就會發現大量使用這種命名方式**。

匈牙利命名法是：變數名 = 屬性（attribute） + 類型（type） + 物件（object）描述，例如：`int iMyAge`，這種命名是一個來自匈牙利的程式設計師在微軟內部推廣起來，然後推廣給了全世界的 Windows 開發人員。

這種命名方式在沒有 IDE 的時代，可以很好地提醒開發人員變數的意義，例如看到 `iMyAge`，就知道它是一個 `int` 型別的變數，而不用找它的定義，缺點是一旦改變變數的屬性，那麼整個專案裡這個變數名字都要改動，所以帶來程式碼維護困難。

**目前 IDE 已經很發達了，都不用標記變數屬性了，IDE 就會幫我們識別了，所以基本沒人用匈牙利命名法了**，雖然我不用 IDE，VIM 大法好。

### 水平留白（程式碼空白）

經常看到有的同學的程式碼都堆在一起，看起來都費勁，或者是有的間隔有空白，有的沒有空白，很不統一，有的同學甚至為了讓程式碼精簡，把所有空白都省略掉了。

大家如果注意我題解上的程式碼風格，我的空白都是有統一規範的。

**我所有題解的 C++ 程式碼，都是嚴格按照 Google C++ 編程規範來的，這樣程式碼看起來就讓人感覺清爽一些**。

我舉一些例子：

運算子（operator）左右一定有空白，例如
```
i = i + 1;
```

分隔符（separator）（`,` 和 `;`）前一位沒有空白，後一位保持空白，例如：

```
int i, j;
for (int fastIndex = 0; fastIndex < nums.size(); fastIndex++)
```

大括號（brace）和函式保持同一行，並有一個空白例如：

```
while (n) {
    n--;
}
```

控制陳述式（control statement）（while，if，for）後都有一個空白，例如：
```
while (n) {
    if (k > 0) return 9;
    n--;
}
```

以下是我剛寫的 LeetCode 283. 移動零的程式碼，大家可以看一下整體風格，注意空白的細節！
```CPP
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int slowIndex = 0;
        for (int fastIndex = 0; fastIndex < nums.size(); fastIndex++) {
            if (nums[fastIndex] != 0) {
                nums[slowIndex++] = nums[fastIndex];
            }
        }
        for (int i = slowIndex; i < nums.size(); i++) {
            nums[i] = 0;
        }
    }
};
```

這裡關於大括號是否要另起一行？

Google 規範是大括號和控制陳述式保持同一行的，我個人也很認可這種寫法，因為可以縮短程式碼的行數，特別是專案中程式碼行數很多的情況下，這種寫法是可以提高閱讀程式碼的效率。

當然我並不是說一定要按照 Google 的規範來，**程式碼風格其實統一就行，沒有嚴格地說誰對誰錯**。
