# 究竟什麼時候用程式館函數，什麼時候要自己實作

在[知識星球](https://programmercarl.com/other/kstar.html)裡有錄友問我，刷題究竟要不要用程式館函數（library function）？刷題的時候總是禁不住程式館函數的誘惑，如果都不用程式館函數一些題目做起來還很麻煩。

估計不少錄友都有這個困惑，我來說一說對於程式館函數的使用。

一些同學可能比較喜歡看 LeetCode 上直接呼叫程式館函數的評論和題解，**其實我感覺娛樂一下還是可以的，但千萬別當真，別沉迷！**

例如：[字串：151. 翻轉字串裡的單詞](../0151.反轉字串裡的單詞.md) 這道題目本身是綜合考察同學們對字串（string）的處理能力，如果 split + reverse 的話，那就失去了題目的意義了。

有的同學可能不屑於實作這麼簡單的功能，直接呼叫程式館函數完事，把字串分成一個個單字，一想就是那麼一回事，多簡單。

相信我，很多面試題都是一想很簡單，實作起來一堆問題。所以刷 LeetCode 本來就是為面試，也為了提高自己的程式碼能力，紮實一點沒壞處。

**那麼平時寫演算法題目就全都不用程式館函數了嗎？**

當然也不是，這裡我給大家提供一個標準。

**如果題目關鍵的部分直接用程式館函數就可以解決，建議不要使用程式館函數**。

**如果程式館函數僅僅是解題過程中的一小部分，並且你已經很清楚這個程式館函數的內部實作原理的話，那麼直接用程式館函數。**

使用程式館函數最大的忌諱就是不知道這個程式館函數怎麼實作的，也不知道其時間複雜度（time complexity），上來就用，這樣寫出來的演算法，時間複雜度自己都掌握不好的。

例如 for 迴圈（for-loop）裡套一個字串的 insert、erase 之類的操作，你說時間複雜度是多少呢，很明顯是 $O(n^2)$ 的時間複雜度了。

在刷題的時候本著我說的標準來使用程式館函數，相信對大家會有所幫助！
