# 程式設計師的履歷應該這麼寫！！（附履歷模板）

Carl 校招社招都拿過大廠的 offer，同時也看過很多應聘者的履歷，這裡把自己總結的履歷技巧以及常見問題給大家梳理一下。

## 履歷篇幅

首先程式設計師（programmer）的履歷力求簡潔明瞭，不用在設計上過於複雜。

對於校招生，一頁履歷就夠了，社招的話兩頁履歷便可。

有的校招生說自己的經歷太多了，履歷要寫出兩三頁，實際上基本是無關內容太多或者描述太囉唆，例如過多的校園活動、學生會經歷等等。

既然是面試技術職位，其他的方面一筆帶過就好。


## 謹慎使用「精通」兩字

應屆生或者剛畢業的程式設計師在寫履歷的時候 **切記不要寫精通某某語言**，如果真的學得很好，**推薦寫「熟悉」或者「掌握」**。

但是有的同學可能僅僅使用一些語言例如 Go 或者 Python 寫了一些小東西，或者了解一些語言的語法，就直接寫上熟悉 C++、Java、Go、Python，這也是大忌，如果 C++ 更了解的話，建議寫熟悉 C++，了解 Java、Go、Python。

**詞語的強烈程度：精通 > 熟悉（推薦使用）> 掌握（推薦使用）> 了解（推薦使用）**

還有做好心理準備，一旦我們寫了熟悉某某語言，這門語言就一定是面試中重點考察的一個點。

例如寫了熟悉 C++，那麼繼承（inheritance）、多型（polymorphism）、封裝（encapsulation）、虛擬函數（virtual function）、C++11 的一些特性、STL 就一定會被問到。

**所以履歷上寫著熟悉哪一門語言，在準備面試的時候重點準備，其他語言幾乎可以不用看了，面試官在面試中通常只會考察一門程式設計語言（programming language）**。


## 拿不準的絕對不要寫在履歷上

**不要為了履歷上看上去很豐富，就寫很多內容上去，內容越多，面試中考點就越多**。

履歷中突出自己技能的幾個點，而不是面面俱到。

想想看，面試官一定是拿著你的履歷開始問問題的，**如果因為僅僅想展示自己多會一點點的東西就都寫在履歷上，等於給自己挖了一個「大陷阱」**。

例如僅僅部署過 nginx 伺服器（server），就在履歷上寫熟悉 nginx，那面試官可能上來就圍繞著 nginx 問很多問題，同學們如果招架不住，然後說：「我僅僅部署過，底層實作我都不了解。」這樣就會讓面試官有些失望。

**同時盡量不要寫程式碼行數 10 萬+ 在履歷上**，這就相當於提高了面試官的期望。

首先就是程式碼行數 10W+ 無從考證，而且這無疑大大提高了面試官的期望和面試官問問題的範圍，這相當於告訴面試官「我寫程式碼沒問題，你就儘管問吧」。

如果履歷上再沒有側重點的話，面試官就開始鋪天蓋地問起來，恐怕大家回答的效果也不會太好。

## 專案經驗應該如何寫

**專案經驗中要突出自己的貢獻**，不要描述一遍專案就完事，要突出自己的貢獻，是添加了哪些功能，還是最佳化了哪些效能指標，最後再說說效益怎麼樣。

例如這個功能被多少人使用，例如效能提升了多少倍。

其實很多同學的一個通病就是在面試中說不出自己專案的難點，專案經歷寫了一大堆，各種框架（framework）、資料庫（database）的使用都寫上了，卻答不出自己專案中的難點。

有的同學可能心裡會想：「自己的專案沒有什麼難點，就是按照功能來做，遇到不會組態（configuration）的不會調整的，就搜尋一下」。

其實大多數人做專案的時候都是這樣的，不是每個專案都有什麼難點，可是為什麼一樣的專案經驗，別人就可以在難點上說出一二三來呢？

這裡還是有一些技巧的，首先是**做專案的時候時刻保持著對難點的敏感程度**，很多我們費盡周折解決了一個問題，然後自己也不做記錄，就忘掉了，**此時如果及時將自己的思考過程記錄下來，就是面試中的重要素材，養成這樣的習慣非常重要**。

很多同學埋怨自己的專案沒難點，其實不然，**找到專案中的一點，深挖下去就會遇到難點，解決它，這種經歷就可以拿來在面試中來說了**。

例如使用 Java 完成的專案，再深挖一下 Java 記憶體（memory）管理，看看是不是可以減少一些虛擬機器（virtual machine）上記憶體的壓力。

所以很多時候 **不是自己的專案沒有難點，而是自己準備得不充分**。

專案經驗是面試官一定會問的，那麼不是每一個面試官都會主動問專案中有哪些亮點或者難點，這時候就需要我們自己主動去說自己專案中的難點。

## 變被動為主動

再說一個面試中如何變被動為主動的技巧，例如自己的專案是一套分散式系統（distributed system），我們在介紹專案的時候主動說：「專案中的難點就是分散式資料一致性（data consistency）的問題。」

**此時就應該知道面試官一定會問：「你是如何解決資料一致性的？」**

如果你對資料一致性協定（protocol）的使用和原理足夠了解的話，就可以和面試官侃侃而談了。

我們在履歷中突出專案的難點在於資料一致性，並且**我們之前就精心準備一致性協定、資料一致性相關的知識，就等著面試官來問**，這樣準備面試更有效率，這樣寫出來的履歷也才是好的履歷，而不是履歷上泛泛而談什麼都說一些，最後都不太了解。

面試一共就三十分鐘或者一個小時，說兩個專案中的難點，既凸顯出自己技術上的深度，同時專案中的難點是最好被我們自己掌控的，**因為這塊是面試官必問的，就是我們可以變被動為主動的關鍵**。

**真正好的履歷是當同學們把自己的履歷遞給面試官的時候，基本都知道面試官看著履歷都會問什麼問題**，然後將面試官引導到自己最熟悉的領域，這樣大家才會佔有主動權。


## 部落格的重要性

履歷上可以放上自己的部落格網址、GitHub 網址甚至社群帳號（如果發了很多關於技術的內容），**透過部落格和 GitHub，面試官就可以快速判斷同學們對技術的熱情，以及學習的態度**，可以讓面試官快速地了解同學們的技術水準。

如果有很多高品質部落格和漂亮的 GitHub 的話，即使面試現場發揮得不好，面試官透過部落格也會知道這位同學基礎還是很紮實，只是發揮得不好而已。

可以看出記錄和總結的重要性。

寫部落格，不一定非要是技術大牛才寫部落格，大家都可以寫部落格來記錄自己的收穫，每一個知識點大家都可以寫一篇技術部落格，這方面要切忌懶惰！

**我是歡迎錄友們參考我的文章寫部落格來記錄自己收穫的，但一定要註明來自公眾號（WeChat Official Account）「代碼隨想錄」呀！**

同時大家對 GitHub 不要畏懼，可以很容易找到一些小的專案來練手。

這裡貼出我的 GitHub，上面有一些我自己寫的小專案，大家可以參考：https://github.com/youngyangyang04

面試只有短短的 30 分鐘或者一個小時，如何把自己掌握的技術更好地展現給面試官呢，部落格、GitHub 都是很好的選擇，如果把這些放在履歷上，面試官一定會看的，這都是加分項。
