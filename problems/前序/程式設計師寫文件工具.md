程式設計師為什麼要學習 Markdown 呢？

那來說一說 Markdown 的好處。

## 為什麼需要 Markdown

大家可能想為什麼要使用 Markdown 來寫文件，而不用各種可以點擊滑鼠點點的那種所見即所得的工具來記筆記，例如 Word、雲端筆記之類的。

首先有如下幾點：

1. Markdown 可以在任何地方使用

**可以使用它來建立網站，筆記，電子書，簡報，郵件資訊和各種技術文件**

2. Markdown 很輕便

事實上，**包含 Markdown 格式文字的檔案可以被任何一個應用程式打開**。

如果感覺不喜歡當前使用的 Markdown 渲染（rendering）應用程式，可以使用其他渲染應用程式來打開。

而鮮明對比的就是 Microsoft Word，必須要使用特定的軟體才能打開 `.doc` 或者 `.docx` 的檔案，而且可能還是亂碼或者格式跑版。

3. Markdown 是跨平台的

**你可以建立 Markdown 格式文字的檔案在任何一個可以執行的作業系統（operating system）上**

4. Markdown 已經無處不在

**程式設計師的世界到處都是 Markdown**，像簡書、GitChat、GitHub、CSDN 等等都支援 Markdown 文件，正宗的官方技術文件都是使用 Markdown 來寫的。

使用 Markdown 不僅可以非常方便地記錄筆記，而且可以直接匯出對應的網站內容，匯出可列印的文件

至於 Markdown 的語法，真的不需要花費很長的時間掌握！

而且一旦你掌握了它，你就可以在任何地方任何平台使用 Markdown 來記錄筆記，文件甚至寫書。

很多人使用 Markdown 來建立網站的內容，但是 Markdown 更加擅長於格式化的文字內容，**使用 Markdown 根本不用擔心格式問題，相容問題**。

很多後端（back end）開發程式設計師的工作環境是 Linux，Linux 下寫文件最佳選擇也是 Markdown。

**我平時寫程式碼，寫文件都習慣在 Linux 系統下進行（包括我的 Mac），所以我更喜歡 Vim + Markdown**。

關於 Vim 的話，後面我也可以單獨介紹一波！

## Markdown 常用語法

我這裡就簡單列舉一些最基本的語法。

### 標題

使用 `#` 可以展現 1-6 級別的標題

```
# 一級標題
## 二級標題
### 三級標題
```

### 列表

使用 `*` 或者 `+` 或者 `-` 或者 `1. ` `2. ` 來表示列表

例如：

```
* 列表1
* 列表2
* 列表3
```

效果：
* 列表1
* 列表2
* 列表3

### 連結

使用 `[名字](url)` 表示連結，例如 `[Github位址](https://github.com/youngyangyang04/Markdown-Resume-Template)`


### 添加圖片

添加圖片 `![名字](圖片位址)` 例如 `![Minion](https://octodex.github.com/images/minion.png)`

### HTML 標籤（tag）

Markdown 支援部分 HTML，例如這樣

```
<center><h1>XXX</h1> </center>
```

## Markdown 渲染

有如下幾種方式渲染 Markdown 文件

* 使用 GitHub 來渲染，也就是把自己的 `.md` 檔案傳到 GitHub 上，就會有視覺化的展現，大家會發現 GitHub 上每個專案都有一個 `README.md`
* 使用 Google 瀏覽器安裝 MarkDown Preview Plus 外掛程式（plugin），也可以打開 Markdown 檔案，但是渲染效果不太好
* Mac 下建議使用 MacDown 來打開 Markdown 檔案，然後就可以直接匯出 PDF 來列印了
* Windows 下可以使用 Typora 來打開 Markdown 檔案，同樣也可以直接匯出 PDF 來列印
