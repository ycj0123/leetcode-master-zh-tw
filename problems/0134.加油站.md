# 134. 加油站

[LeetCode 題目連結](https://leetcode.cn/problems/gas-station/)

在一條環路上有 N 個加油站，其中第 i 個加油站有汽油 gas[i] 升。

你有一輛油箱容量無限的汽車，從第 i 個加油站開往第 i+1 個加油站需要消耗汽油 cost[i] 升。你從其中的一個加油站出發，開始時油箱為空。

如果你可以繞環路行駛一週，則回傳出發時加油站的編號，否則回傳 -1。

說明: 

* 如果題目有解（solution），該答案即為唯一答案。
* 輸入陣列（array）均為非空陣列，且長度相同。
* 輸入陣列中的元素（element）均為非負數。

範例 1:
輸入:
* gas  = [1,2,3,4,5]
* cost = [3,4,5,1,2]

輸出: 3
解釋:
* 從 3 號加油站(索引（index）為 3 處)出發，可獲得 4 升汽油。此時油箱有 = 0 + 4 = 4 升汽油
* 開往 4 號加油站，此時油箱有 4 - 1 + 5 = 8 升汽油
* 開往 0 號加油站，此時油箱有 8 - 2 + 1 = 7 升汽油
* 開往 1 號加油站，此時油箱有 7 - 3 + 2 = 6 升汽油
* 開往 2 號加油站，此時油箱有 6 - 4 + 3 = 5 升汽油
* 開往 3 號加油站，你需要消耗 5 升汽油，正好足夠你返回到 3 號加油站。
* 因此，3 可為起始索引。

範例 2:
輸入:
* gas  = [2,3,4]
* cost = [3,4,3]

* 輸出: -1
* 解釋:
你不能從 0 號或 1 號加油站出發，因為沒有足夠的汽油可以讓你行駛到下一個加油站。我們從 2 號加油站出發，可以獲得 4 升汽油。 此時油箱有 = 0 + 4 = 4 升汽油。開往 0 號加油站，此時油箱有 4 - 3 + 2 = 3 升汽油。開往 1 號加油站，此時油箱有 3 - 3 + 3 = 3 升汽油。你無法返回 2 號加油站，因為返程需要消耗 4 升汽油，但是你的油箱只有 3 升汽油。因此，無論怎樣，你都不可能繞環路行駛一週。

## 解題思路


### 蠻力（brute force）方法

蠻力的方法很明顯就是 O(n^2) 的，遍歷（traversal）每一個加油站為起點的情況，模擬（simulation）一圈。

如果跑了一圈，中途沒有斷油，而且最後油量大於等於 0，說明這個起點是 ok 的。

蠻力的方法想法比較簡單，但程式碼寫起來也不是很容易，關鍵是要模擬跑一圈的過程。

**for 迴圈（for-loop）適合模擬從頭到尾的遍歷，而 while 迴圈（while loop）適合模擬環形遍歷，要善於使用 while！**

C++ 程式碼如下：

```CPP
class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        for (int i = 0; i < cost.size(); i++) {
            int rest = gas[i] - cost[i]; // 記錄剩餘油量
            int index = (i + 1) % cost.size();
            while (rest > 0 && index != i) { // 模擬以i為起點行駛一圈（如果有rest==0，那麼答案就不唯一了）
                rest += gas[index] - cost[index];
                index = (index + 1) % cost.size();
            }
            // 如果以i為起點跑一圈，剩餘油量>=0，回傳該起始位置
            if (rest >= 0 && index == i) return i;
        }
        return -1;
    }
};
```

* 時間複雜性（time complexity）：O(n^2)
* 空間複雜度（space complexity）：O(1)


### 貪心演算法（方法一）

直接從全局進行貪心（greedy）選擇，情況如下：

* 情況一：如果 gas 的總和小於 cost 總和，那麼無論從哪裡出發，一定是跑不了一圈的
* 情況二：rest[i] = gas[i]-cost[i] 為一天剩下的油，i 從 0 開始計算累加到最後一站，如果累加沒有出現負數，說明從 0 出發，油就沒有斷過，那麼 0 就是起點。

* 情況三：如果累加的最小值是負數，汽車就要從非 0 節點（node）出發，從後向前，看哪個節點能把這個負數填平，能把這個負數填平的節點就是出發節點。

C++ 程式碼如下：

```CPP
class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int curSum = 0;
        int min = INT_MAX; // 從起點出發，油箱裡的油量最小值
        for (int i = 0; i < gas.size(); i++) {
            int rest = gas[i] - cost[i];
            curSum += rest;
            if (curSum < min) {
                min = curSum;
            }
        }
        if (curSum < 0) return -1;  // 情況1
        if (min >= 0) return 0;     // 情況2
                                    // 情況3
        for (int i = gas.size() - 1; i >= 0; i--) {
            int rest = gas[i] - cost[i];
            min += rest;
            if (min >= 0) {
                return i;
            }
        }
        return -1;
    }
};
```
* 時間複雜性：O(n)
* 空間複雜度：O(1)

**其實我不認為這種方式是貪心演算法，因為沒有找出局部最佳，而是直接從總體最佳（global optimum）的角度上思考問題**。

但這種解法又說不出是什麼方法，這就是一個從全局角度選取最佳解的模擬操作。

所以對於本解法是貪心，我持保留意見！

但不管怎麼說，解法畢竟還是巧妙的，不用過於執著於其名字稱呼。

### 貪心演算法（方法二）

可以換一個想法，首先如果總油量減去總消耗大於等於零那麼一定可以跑完一圈，說明各個站點的加油站剩油量 rest[i] 相加一定是大於等於零的。

每個加油站的剩餘量 rest[i] 為 gas[i] - cost[i]。

i 從 0 開始累加 rest[i]，和記為 curSum，一旦 curSum 小於零，說明 [0, i] 區間（interval）都不能作為起始位置，因為這個區間選擇任何一個位置作為起點，到 i 這裡都會斷油，那麼起始位置從 i+1 算起，再從 0 計算 curSum。

如圖：

![](https://file1.kamacoder.com/i/algo/20230117165628.png)

那麼為什麼一旦 [0，i] 區間和為負數，起始位置就可以是 i+1 呢，i+1 後面就不會出現更大的負數？

如果出現更大的負數，就是更新 i，那麼起始位置又變成新的 i+1 了。

那有沒有可能 [0，i] 區間選某一個作為起點，累加到 i 這裡 curSum 是不會小於零呢？  如圖： 

![](https://file1.kamacoder.com/i/algo/20230117170703.png)

如果 curSum < 0 說明 區間和1 + 區間和2 < 0，那麼假設從上圖中的位置開始計數 curSum 不會小於 0 的話，就是 區間和2 > 0。 

區間和1 + 區間和2 < 0 同時 區間和2 > 0，只能說明區間和1 < 0，那麼就會從假設的箭頭處就開始重新選擇起始位置了。 


**那麼局部最佳：當前累加 rest[i] 的和 curSum 一旦小於 0，起始位置至少要是 i+1，因為從 i 之前開始一定不行。總體最佳：找到可以跑一圈的起始位置**。

局部最佳可以推出總體最佳，找不出反例，試試貪心！

C++ 程式碼如下：

```CPP
class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int curSum = 0;
        int totalSum = 0;
        int start = 0;
        for (int i = 0; i < gas.size(); i++) {
            curSum += gas[i] - cost[i];
            totalSum += gas[i] - cost[i];
            if (curSum < 0) {   // 目前累加rest[i]和 curSum一旦小於0
                start = i + 1;  // 起始位置更新為i+1
                curSum = 0;     // curSum從0開始
            }
        }
        if (totalSum < 0) return -1; // 說明怎麼走都不可能跑一圈了
        return start;
    }
};
```
* 時間複雜性：O(n)
* 空間複雜度：O(1)

**說這種解法為貪心演算法，才是有理有據的，因為總體最佳解是根據局部最佳推導出來的**。

## 總結

對於本題首先給出了蠻力解法，蠻力解法模擬跑一圈的過程其實比較考驗程式碼技巧的，要對 while 使用得很熟練。

然後給出了兩種貪心演算法，對於第一種貪心方法，其實我認為就是一種直接從全局選取最佳的模擬操作，思路還是很巧妙的，值得學習一下。

對於第二種貪心方法，才真正體現出貪心的精髓，用局部最佳可以推出總體最佳，進而求得起始位置。

### C 

貪心演算法：方法一


```c
int canCompleteCircuit(int* gas, int gasSize, int* cost, int costSize){
    int curSum = 0;
    int i;
    int min = INT_MAX;
    //遍歷整個陣列。計算出每站的用油差。並將其與最小累加量比較
    for(i = 0; i < gasSize; i++) {
        int diff = gas[i] - cost[i];
        curSum += diff;
        if(curSum < min)
            min = curSum;
    }
    //若汽油總數為負數，代表無法跑完一環。回傳-1
    if(curSum < 0)
        return -1;
    //若min大於等於0，說明每一天加油量比用油量多。因此從0出發即可
    if(min >= 0)
        return 0;
    //若累加最小值為負，則找到一個非零元素（加油量大於出油量）出發。回傳座標
    for(i = gasSize - 1; i >= 0; i--) {
        min+=(gas[i]-cost[i]);
        if(min >= 0)
            return i;
    }
    //邏輯上不會回傳這個0
    return 0;
```

貪心演算法：方法二
```c
int canCompleteCircuit(int* gas, int gasSize, int* cost, int costSize){
    int curSum = 0;
    int totalSum = 0;
    int start = 0;

    int i;
    for(i = 0; i < gasSize; ++i) {
        // 目前i站中加油量與耗油量的差
        int diff = gas[i] - cost[i];

        curSum += diff;
        totalSum += diff;

        // 若0到i的加油量都為負，則開始位置應為i+1
        if(curSum < 0) {
            curSum = 0;
            // 當i + 1 == gasSize時，totalSum < 0（此時i為gasSize - 1)，汽車不可能返回原點
            start = i + 1;
        }
    }

    // 若總和小於0，加油車無論如何都無法返回原點。回傳-1
    if(totalSum < 0)
        return -1;

    return start;
}
```

```scala
object Solution {
  def canCompleteCircuit(gas: Array[Int], cost: Array[Int]): Int = {
    for (i <- cost.indices) {
      var rest = gas(i) - cost(i)
      var index = (i + 1) % cost.length // index為i的下一個節點
      while (rest > 0 && i != index) {
        rest += (gas(index) - cost(index))
        index = (index + 1) % cost.length
      }
      if (rest >= 0 && index == i) return i
    }
    -1
  }
```

```scala
object Solution {
  def canCompleteCircuit(gas: Array[Int], cost: Array[Int]): Int = {
    var curSum = 0
    var min = Int.MaxValue
    for (i <- gas.indices) {
      var rest = gas(i) - cost(i)
      curSum += rest
      min = math.min(min, curSum)
    }
    if (curSum < 0) return -1 // 情況1: gas的總和小於cost的總和，不可能到達終點
    if (min >= 0) return 0 // 情況2: 最小值>=0，從0號出發可以直接到達
    // 情況3: min為負值，從後向前看，能把min填平的節點就是出發節點
    for (i <- gas.length - 1 to 0 by -1) {
      var rest = gas(i) - cost(i)
      min += rest
      if (min >= 0) return i
    }
    -1
  }
}
```
