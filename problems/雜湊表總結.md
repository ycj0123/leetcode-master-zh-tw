# 雜湊表總結篇


## 雜湊表理論基礎

在[關於雜湊表，你該了解這些！](https://programmercarl.com/哈希表理论基础.html)中，我們介紹了雜湊表的基礎理論知識，不同於枯燥的講解，這裡介紹的都是對刷題有幫助的理論知識點。

**一般來說雜湊表都是用來快速判斷一個元素（element）是否出現在集合（set）裡**。

對於雜湊表，要知道**雜湊函數（hash function）**和**散列碰撞（hash collision）**在雜湊表中的作用。

雜湊函數是把傳入的 key 映射（map / mapping）到 symbol table 的索引（index）上。

散列碰撞處理有多個 key 映射到相同索引上時的情景，處理碰撞的普遍方式是 chaining 和 linear probing。

接下來是常見的三種雜湊（hash）結構：

* 陣列（array）
* set（集合）
* map（映射）

在 C++ 語言中，set 和 map 都分別提供了三種資料結構（data structure），每種資料結構的底層實作和用途都有所不同，在[關於雜湊表，你該了解這些！](https://programmercarl.com/哈希表理论基础.html)中我給出了詳細分析，這一知識點很重要！

例如什麼時候用 std::set，什麼時候用 std::multiset，什麼時候用 std::unordered_set，都是很有講究的。

**只有對這些資料結構的底層實作很熟悉，才能靈活使用，否則很容易寫出效率低下的程式**。

## 雜湊表經典題目

### 陣列作為雜湊表

一些應用場景就是為陣列量身定做的。

在[242. 有效的迴文（anagram）](https://programmercarl.com/0242.有效的字母异位词.html)中，我們提到了陣列就是簡單的雜湊表，但是陣列的大小是受限的！

這道題目包含小寫字母，那麼使用陣列來做雜湊最合適不過。

在[383. 贖金信](https://programmercarl.com/0383.赎金信.html)中同樣要求只有小寫字母，那麼就給我們濃濃的暗示，用陣列！

本題和[242. 有效的迴文（anagram）](https://programmercarl.com/0242.有效的字母异位词.html)很像，[242. 有效的迴文（anagram）](https://programmercarl.com/0242.有效的字母异位词.html)是求字串（string） a 和字串 b 是否可以相互組成，在[383. 贖金信](https://programmercarl.com/0383.赎金信.html)中是求字串 a 能否組成字串 b，而不用管字串 b 能不能組成字串 a。

一些同學可能想，用陣列幹嘛，都用 map 不就完事了。

**上面兩道題目用 map 確實可以，但使用 map 的空間消耗要比陣列大一些，因為 map 要維護紅-黑樹（red-black tree）或者 symbol table，而且還要做雜湊函數的運算。所以陣列更加簡單直接有效！**


### set 作為雜湊表

在[349. 兩個陣列的交集（intersection）](https://programmercarl.com/0349.两个数组的交集.html)中我們給出了什麼時候用陣列就不行了，需要用 set。

這道題目沒有限制數值的大小，就無法使用陣列來做雜湊表了。

**主要因為如下兩點：**

* 陣列的大小是有限的，受到系統堆疊空間（stack space）（不是資料結構的堆疊（stack））的限制。
* 如果陣列空間夠大，但雜湊值比較少、特別分散、跨度非常大，使用陣列就造成空間的極大浪費。

所以此時一樣要做映射的話，就可以使用 set 了。

關於 set，C++ 提供了如下三種可用的資料結構：（詳情請看[關於雜湊表，你該了解這些！](https://programmercarl.com/哈希表理论基础.html)）

* std::set
* std::multiset
* std::unordered_set

std::set 和 std::multiset 底層實作都是紅-黑樹，std::unordered_set 的底層實作是雜湊，使用 unordered_set 讀寫效率是最高的，本題並不需要對資料進行排序（sorting），而且還不要讓資料重複（duplicate），所以選擇 unordered_set。

在[202. 快樂數](https://programmercarl.com/0202.快乐数.html)中，我們再次使用了 unordered_set 來判斷一個數是否重複出現過。


### map 作為雜湊表

在[1. 兩數之和](https://programmercarl.com/0001.两数之和.html)中 map 正式登場。

來說一說：使用陣列和 set 來做雜湊法的局限。

* 陣列的大小是受限制的，而且如果元素很少，而雜湊值太大會造成記憶體（memory）空間的浪費。
* set 是一個集合，裡面放的元素只能是一個 key，而兩數之和這道題目，不僅要判斷 y 是否存在而且還要記錄 y 的下標（subscript）位置，因為要回傳 x 和 y 的下標。所以 set 也不能用。

map 是一種`<key, value>`的結構，本題可以用 key 保存數值，用 value 來保存數值所在的下標。所以使用 map 最為合適。

C++ 提供如下三種 map：（詳情請看[關於雜湊表，你該了解這些！](https://programmercarl.com/哈希表理论基础.html)）

* std::map
* std::multimap
* std::unordered_map

std::unordered_map 底層實作為雜湊，std::map 和 std::multimap 的底層實作是紅-黑樹。

同理，std::map 和 std::multimap 的 key 也是有序的（ordered）（這個問題也經常作為面試題，考察對語言容器（container）底層的理解），[1. 兩數之和](https://programmercarl.com/0001.两数之和.html)中並不需要 key 有序，選擇 std::unordered_map 效率更高！

在[454. 四數相加](https://programmercarl.com/0454.四数相加II.html)中我們提到了其實需要雜湊的地方都能找到 map 的身影。

本題乍看之下好像和[18. 四數之和](https://programmercarl.com/0018.四数之和.html)、[15. 三數之和](https://programmercarl.com/0015.三数之和.html)差不多，其實差很多！

**關鍵差別是本題為四個獨立的陣列，只要找到 A[i] + B[j] + C[k] + D[l] = 0 就可以，不用考慮重複問題，而[18. 四數之和](https://programmercarl.com/0018.四数之和.html)、[15. 三數之和](https://programmercarl.com/0015.三数之和.html)是一個陣列（集合）裡找到和為 0 的組合（combination），可就難很多了！**

用雜湊法解決了兩數之和，很多同學會感覺用雜湊法也可以解決三數之和、四數之和。

其實是可以解決，但是非常麻煩，需要進行 deduplication 導致程式碼效率很低。

在[15. 三數之和](https://programmercarl.com/0015.三数之和.html)中我給出了雜湊法和 two pointers 兩個解法，大家就可以體會到，使用雜湊法還是比較麻煩的。

所以 18. 四數之和、15. 三數之和都推薦使用 two pointers 法！
