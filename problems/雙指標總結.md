> 又是一波總結

相信大家已經對雙指標（two pointers）法很熟悉了，但是雙指標法並不隸屬於某一種資料結構，我們在講解陣列（array）、鏈接串列（linked list）、字串（string）都用到了雙指標法，所以有必要針對雙指標法做一個總結。

# 雙指標總結篇
## 陣列篇

在[陣列：就移除個元素（element）很難嗎？](./0027.移除元素.md)中，原地（in-place）移除陣列上的元素，我們說到了陣列上的元素，不能真正的刪除（delete），只能覆蓋。

一些同學可能會寫出如下程式碼（pseudocode）：

```
for (int i = 0; i < array.size(); i++) {
    if (array[i] == target) {
        array.erase(i);
    }
}
```

這個程式碼看上去好像是 O(n) 的時間複雜度（time complexity），其實是 O(n^2) 的時間複雜度，因為 erase 操作也是 O(n) 的操作。

所以此時使用雙指標法才展現出效率的優勢：**透過兩個指標（pointer）在一個 for 迴圈（for-loop）下完成兩個 for 迴圈的工作。**

## 字串篇

在[字串：這道題目，使用程式館函數（library function）一行程式碼搞定](./0344.反轉字串.md)中講解了反轉（reverse）字串，注意這裡強調要原地反轉，要不然就失去了題目的意義。

使用雙指標法，**定義兩個指標（也可以說是索引（index）下標（subscript）），一個從字串前面，一個從字串後面，兩個指標同時向中間移動，並交換（swap）元素。**，時間複雜度是 O(n)。

在[替換空白](./劍指Offer05.替換空格.md) 中介紹使用雙指標填充字串的方法，如果想把這道題目做到極致，就不要只用額外的輔助空間（auxiliary space）了！

解題思路就是**首先擴充陣列到每個空白替換成 "%20" 之後的大小。然後雙指標從後向前替換空白。**

有同學問了，為什麼要從後向前填充，從前向後填充不行嗎？

從前向後填充就是 O(n^2) 的演算法了，因為每次添加元素都要將添加元素之後的所有元素向後移動。

**其實很多陣列（字串）填充類的問題，都可以先預先給陣列擴容到填充後的大小，然後再從後向前進行操作。**

那麼在[字串：花式反轉還不夠！](./0151.反轉字串裡的單詞.md)中，我們使用雙指標法，用 O(n) 的時間複雜度完成字串刪除類的操作，因為題目要刪除冗餘（redundant）空白。

**在刪除冗餘空白的過程中，如果不注意程式碼效率，很容易寫成了 O(n^2) 的時間複雜度。其實使用雙指標法 O(n) 就可以搞定。**

**主要還是大家用 erase 用得比較隨意，一定要注意 for 迴圈下用 erase 的情況，一般可以用雙指標寫效率更高！**

## 鏈接串列篇

翻轉鏈接串列是現場面試，白紙寫程式碼的好題，考察了候選者對鏈接串列以及指標的熟悉程度，而且程式碼也不長，適合在白紙上寫。

在[鏈接串列：聽說過兩天反轉鏈接串列又寫不出來了？](./0206.反轉鏈接串列.md)中，講如何使用雙指標法來翻轉鏈接串列，**只需要改變鏈接串列的 next 指標的指向，直接將鏈接串列反轉，而不用重新定義一個新的鏈接串列。**

解題思路還是很簡單的，程式碼也不長，但是想在白紙上一次性寫出無錯誤（bug-free）的程式碼，並不是容易的事情。

在鏈接串列中求環，應該是雙指標在鏈接串列裡最經典的應用，在[鏈接串列：環找到了，那入口呢？](./0142.環形鏈接串列II.md)中講解了如何透過雙指標判斷是否有環，而且還要找到環的入口。

**使用快慢指標（fast and slow pointers）（two pointers 法），分別定義 fast 和 slow 指標，從頭節點（head node）出發，fast 指標每次移動兩個節點（node），slow 指標每次移動一個節點，如果 fast 和 slow 指標在途中相遇，說明這個鏈接串列有環。**

那麼找到環的入口，其實需要點簡單的數學推理，我在文章中把找環的入口清清楚楚地推理了一遍，如果對找環入口不夠清楚的同學建議自己看一看[鏈接串列：環找到了，那入口呢？](./0142.環形鏈接串列II.md)。

## N 數之和篇

在[雜湊表（hash table）：解決了兩數之和，那麼能解決三數之和嗎？](./0015.三數之和.md)中，講到使用雜湊（hash）法可以解決 1. 兩數之和的問題

其實使用雙指標也可以解決 1. 兩數之和的問題，只不過 1. 兩數之和求的是兩個元素的下標，沒法用雙指標，如果改成求具體兩個元素的數值就可以了，大家可以嘗試用雙指標做一個 LeetCode 上兩數之和的題目，就可以體會到我說的意思了。

使用了雜湊法解決了兩數之和，但是雜湊法並不適用於三數之和！

使用雜湊法的過程中要把符合條件的三元組（triple）放進 vector 中，然後再去進行去重（deduplication），這樣是非常費時的，很容易逾時，也是三數之和通過率如此之低的根源所在。

去重的過程不好處理，有很多小細節，如果在面試中很難想到位。

時間複雜度可以做到 O(n^2)，但還是比較費時的，因為不好做修剪法（pruning）操作。

所以這道題目使用雙指標法才是最為合適的，用雙指標做這道題目才能真正體會到，**透過前後兩個指標不斷向中間逼近，在一個 for 迴圈下完成兩個 for 迴圈的工作。**

只用雙指標法時間複雜度為 O(n^2)，但比雜湊法的 O(n^2) 效率高得多，雜湊法在使用兩層 for 迴圈的時候，能做的修剪法操作很有限。

在[two pointers 法：一樣的道理，能解決四數之和](./0018.四數之和.md)中，講到了四數之和，其實思路是一樣的，**在三數之和的基礎上再套一層 for 迴圈，依然是使用雙指標法。**

對於三數之和，使用雙指標法就是將原本蠻力（brute force） O(n^3) 的解法，降為 O(n^2) 的解法，四數之和的雙指標解法就是將原本蠻力 O(n^4) 的解法，降為 O(n^3) 的解法。

同樣的道理，五數之和，n 數之和都是在這個基礎上累加。
